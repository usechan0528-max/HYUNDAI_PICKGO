# 동선 기반 픽업 지점 추천

## 2026-11-04 최종 사용자 기준 및 구현

최신 지시가 앞선 대장 중심·미확인 제외 기준보다 우선한다. 잠깐의 정차도 금지된 지점, 일반차 이용 불가 전용 공간, 폐쇄·차량 접근 불가 및 건물 내부/고속도로 차로 등 비정상 위치는 추천과 선택에서 차단한다. 공식 승하차 지정과 `pickupAllowed=true`, 60초 이상 허용은 필수 조건이 아니다. 그 외 미확인 조건은 안내하면서 사용자 책임으로 선택할 수 있다. 주차만 금지된 곳과 정차 자체가 금지된 곳을 구분하며 CCTV 존재만으로 정차 금지라고 판정하지 않는다. 현장 표지·교통 상황 확인과 실제 정차 판단 책임은 사용자에게 있다.

`eligibility.mjs` 공통 판정, engine의 선택 가능한 후보 평가, board의 선택/수락 재평가 및 수동 생성·제안·수락 제한 검사, 화면의 미확인 안내를 구현했다. 금지 사실이 누락·오래된 응답으로 사라지지 않도록 보존하고 새로운 명시적 해제 정보로만 갱신한다. 합성 공급자는 공식 지정이 없는 일반 도로변을 시연한다. 실제 지도/금지영역 폴리곤/도로 스냅과 임의 지도 핀 UI는 아직 미연동이다. 현재 선택 범위는 기존 이름 기반 장소 목록이며 전국 임의 좌표의 불법 여부를 판별하는 기능이 완료된 것은 아니다.

현재 사례 기준점은 현대자동차 양재사옥. [양재 후보·구현·검증 기록](PICKUP_YANGJAE_2026-11-04.md)을 따른다. 아래 11월 3일 문구와 11월 4일 초기 설계는 과거 기록이다.

## 2026-11-04 추천 기준 변경

사용자 지시로 공식 지정 승하차 구역에 한정하지 않고, 일반 승용차가 택시처럼 짧게 승하차할 수 있는 일반 도로변·시설 앞 공간까지 후보 조사 범위를 확장한다. 대중교통/택시 전용 공간과 주정차 금지·단속 구역은 제외한다. 제한 여부 미확인과 제한 없음 확인은 구분한다. [최신 조사·선정 기준](PICKUP_GANGNAM_DATA_2026-11-03.md)을 따른다.

아래 대장 중심 적격성·`maxDwellSeconds` 계약은 11월 3일 합성 구현의 설명이다. 실제 공급자 계약은 ‘공식 승하차 지정’ 대신 일반 승용차의 짧은 승하차 적합성 근거를 수용하도록 후속 변경해야 한다. 공식 대장 부재만으로 조사 후보를 탈락시키지 않는다. 예상 승하차 소요시간을 법적 허용시간으로 해석하지 않는다.

이번 변경은 사용자 결정과 설계·조사 기준 반영이다. 추천 엔진·공급자 코드와 실데이터 수집 차단은 변경하지 않았다. 후속 구현의 수용 조건: (1) 공식 지정이 없는 일반 후보도 제한·접근 근거를 갖추면 평가 가능, (2) 전용/금지/단속 후보 제외, (3) 미확인을 허용으로 자동 변환하지 않음, (4) 동선·보행 비교와 양측 수락 유지. 현재 로컬의 별도 작업 변경은 보존한다.

상태: 합성 세로 흐름 구현·검증, 실제 실시간 기능은 미완료. 사용자 승인: 양측 실시간 위치와 차량 동선을 이용해 잠시 세우기 좋은 지점을 추천. 후속 사용자 지정 첫 실제 검증 지역은 **강남역**. J-01과 무관한 픽업 기능이다.

## 구현 범위

`experiments/pickup-board/recommendation/`에 서버 소유 provider 계약, 후보 적격성·점수 엔진, 회차별 연속 동의 저장소, 브라우저 수명주기 controller, 터치 화면과 명시 합성 서버를 추가했다. `server.mjs`에는 기본 RecommendationBoard(PhoneBoard 상속), 정적 경로 및 인증된 recommendation GET/POST를 연결했다. `index.html` 추천 링크 추가 후 두 공통파일을 탑승자 웹 담당에게 반환했고, 해당 담당의 HTTPS/초대 재시도 변경을 보존했다. 기존 일회 위치 동의를 연속 공유로 사용하지 않는다.

일반 실행 `node experiments/pickup-board/server.mjs`의 실제 provider는 unavailable이다. 화면뿐 아니라 서버에서도 모든 추천용 grant/publish를 거부한다. 실제 좌표 수집·외부 전송 없이 수동 약속을 계속 쓸 수 있다. 기존 일회 위치 API는 별도 기존 동의 경로다.

합성 시연은 `node experiments/pickup-board/recommendation/demo-server.mjs` 후 http://127.0.0.1:4187 에서 시작한다. 회차 생성→상대 참여→각자 추천 화면에서 서쪽/동쪽 합성 위치 공유에 별도 동의→현재 위치로 다시 추천→후보 터치 제안→상대 추천 화면에서 최신 근거 확인 후 수락. 실제 위치 권한을 요청하지 않는다. 합성 좌표·방향별 도로 비용·보행 비용·정차 대장 모두 fixture이며 실제 지도나 차량 경로가 아니다. 가상 장소 이름을 강남역 실재 장소로 바꾸지 않았다.

## 적격성과 정책

- 위치는 관측 나이(클라이언트 자기보고)+서버 단조 경과 15초 미만, 정확도 50m 이하. 미래·비수치·범위 오류·단조시계 역행 거부. 실제 위치 진실성이나 SDK 시계 계약을 증명하지 않는다.
- 경로는 양측 fix ID 및 route ID, source mode에 결합. 차량 도달·합법 진입방향과 실제 보행 그래프 경로를 모두 요구한다. 직선거리로 보행시간을 계산하지 않는다.
- 정차 근거는 동일 승하차 입구 ID·출처·참조·확인시각·유효구간·허용차량·승하차 허용·금지/폐쇄 여부·최대 정차시간을 요구한다. unknown은 제외한다. 도착 예상 중 늦은 쪽+60초 정차+60초 여유가 근거 유효구간 안에 있어야 한다. 근거 확인 후 15분 제한은 합성 개발 정책이며 실제 데이터원별 갱신 SLA는 미결정이다.
- 적격 후보 최대3개를 `차량 우회초 + 보행초 + 유턴 횟수×120초` 오름차순으로 제시한다. 동점은 ID순. 검증 전 제품 가중치이며 후보 집합 내 순위이지 전역 최적화·안전 보장이 아니다. 현재 합성 도로는 위치가 서쪽/동쪽 구간인지로 비용표를 선택하는 최소 그래프 fixture다. 실제 차량 진행 경로의 계산·실시간 교통 반영은 없다.
- 계산 결과는 최대5초 유효. 새 위치·약속 버전 변경·철회·종료·탑승·만료는 선택 무효화. 수락은 새로운 provider 평가와 입력 revision/회차 version CAS 후 기존 Board 상대 수락을 실행한다. 일반 actions 경로는 추천 제안을 우회 수락하지 못한다. 재계산만으로 확정 장소는 변하지 않는다.
- 추천 제안은 사용자 합의 의도로 남으며 자동 삭제하지 않는다. 최소 proposal/candidate ID 연결을 보존해야 기존 actions의 우회 수락을 막는다. 유효한 근거가 없으면 수락을 거부하고 거절/철회를 허용한다. 파생 경로 요약은 위치/동의 소실 시 제거한다.
