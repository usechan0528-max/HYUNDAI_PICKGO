# Gleo 공존 앱의 미충족 영역 조사

확인일: 2026-11-02 KST. 작성: Codex. 독립 비평: Claude Opus 5.5 3회. 공식 자료 보완: Dot DOT-R005, 후속 DOT-R006.

## 결론과 조사 한계

J1의 일반적인 설명인 운행 상황·취향 기반 추천과 선택 후 연속 청취는 이미 직접 경쟁 서비스가 표방한다. 특히 픽클을 빼고 멜론만 비교한 기존 평가는 경쟁 범위가 불충분했다. 현 상태에서 J1의 독창성이나 기존 서비스의 품질 부족을 주장할 근거가 없다. 이는 구현 자산 폐기나 D-014 변경 승인이 아니다.

우선 반증 조사 대상으로 삼은 것은 **여러 운행에 걸친 미완료 용무를 보관하고, 이번 이동에서 처리 가능한 일만 시간·마감·우회 제약과 함께 제안하는 서비스**다. 후속 조사에서 스마트폰 리마인더의 지속 상태·완료 처리, 기존 경로 제품의 방문 시간창 최적화까지 확인했다. 따라서 이 후보도 새 기능이나 새 알고리즘으로 추천할 근거가 부족하다. 남는 것은 일반 차주의 입력·누락·수동 재계획을 줄이는 통합 사용성 가설이며, 부재·반복 수요·우월성은 미입증이다. 나머지 후보를 억지로 유망하다고 선정하지 않는다.

“모든 현대차 앱 확인 완료”는 아니다. 국내 일반 차주의 차량 이용을 중심으로 현대닷컴 모바일 앱 목록, 한국 App Store/Google Play 공식 게시자, Pleos 공식 발표 및 개별 서비스 공식 페이지를 조사했다. 전 세계 지역별 앱, 사내·판매·상용 서비스 전체의 기능 실험과 실제 차량 앱마켓 전수 목록은 확보하지 못했다. 2026-09 발표의 총18종을 현재 개수로 쓰지 않는다. 자료에 명칭이 있는 것과 현재 계정·차종에서 설치/실행 가능한 것을 구분한다.

## 증거 판정

- 공식 현행 소개: 서비스 제공자가 공개한 기능. 실제 실행 성공·품질 입증 아님.
- 발표 당시 제공/예정: 발표일과 시제를 보존. 최신 버전 전체에 적용하지 않음.
- 에뮬레이터 UI 관찰: 화면·메뉴·도움말 확인. 음성 명령 성공과 구분.
- 가설: 아래 후보 및 비교 우선순위. 시장 부재·심각한 부족이라는 확정 표현 금지.

### 앱 목록의 포괄성 점검

9월 추가7종은 카카오내비, what3words, Make My Day–Route Planner, 멜론, Radioline, RaiDIO Auto, 픽클이다. 초기 자료에 네이버 오토/지도, YouTube, Spotify, SBS고릴라, essential;, Genie가 나오고 네이버의 6월 발표는 Whale 제공도 설명한다. 이 명칭들을 더해 9월의 정확한 전체 목록을 재구성하지 않는다. 별도 패키지/서비스 구분, 삭제/추가/차종 차이 미확인이다.

현대닷컴 공식 모바일 앱 안내에는 마이현대, 현대 제네시스 셀렉션, Hyundai N, 운전결심이 나온다. 한국 App Store 공식 게시자에서 마이현대/MY GENESIS 외에 현대·제네시스 인증중고차, 셀렉션, 이응패스, C-TourBus, H-Mate, Autoway, Hi 비서(지점/대리점), 울산공장 출입인증/MDM 명칭을 확인했다. Google Play 게시자에는 Mpass도 나타난다. 판매·업무·출입인증 명칭을 차량 탑재 앱으로 세지 않았다. [S14][S16][S17]

공식 목록 간 노출 차이와 E-pit 같은 별도 상세 페이지의 존재 때문에 어느 게시자 화면 하나를 전체 카탈로그로 취급하지 않는다. 과거 앱명 Bluelink/CarPay/Digital Key/Built-in Cam이 독립 앱이었는지, 현재 통합 서비스인지도 구분해야 한다. 검색 결과에 나온 옛 앱을 현행으로 나열하지 않았다.

## 남는 공백 가설과 반례

### 우선 반증 대상: 이번 길에서 끝낼 일

문제 가설: 일반 차주가 이미 기록한 구매·수거·반품 등을 잊거나, 방문했지만 마감/조건 때문에 처리하지 못하는 일이 반복된다. 반복 빈도는 미측정이다.

예시: 어제 보류한 세탁물 수거, 내일까지인 반품, 귀가 전 구매를 저장해 두었다. 오늘은 추가 이동10분 이내이고 세탁소는19시에 닫는다. 앱은 확인 가능한 조건 안에서 오늘 가능한 일과 보류할 일을 구분하고, 완료 확인 후 다음 운행에 다시 제안하지 않는다. 숫자는 합성 시나리오이며 실제 ETA·영업·반품 정책 검증값이 아니다.

Gleo가 맡을 제안 역할: 요청 이해, 앱 기능 호출, 필요한 확인 질문, 결과 전달. 앱이 맡을 제안 역할: 할 일과 기한의 지속 상태, 완료/보류/만료, 허용 우회 등 사용자 제약, 근거 있는 실행 가능성 계산. 경로 생성·길 안내는 기존 내비 역할. 다른 앱 데이터나 결제 권한이 자동 제공된다는 뜻은 아니다.

차별성이 남으려면 **일반 리마인더+Gleo 경로검색+경유지**보다 누락과 수동 재계획을 줄여야 한다. 단순 위치 알림, 일정을 읽고 길 안내, 오늘의 할 일 요약은 후보의 핵심 가치로 인정하지 않는다. 영업시간·재고·반품 자격·교통 데이터가 없으면 모른다고 표시해야 하며 “처리 가능”을 보장하지 않는다.

실행 가능한 다음 조사: 동일한 합성 입력으로 (1) 마감이 겹치는 두 용무 (2) 어제 보류→오늘 재판단 (3) 한 용무 완료→다음 운행에서 제외의 세 경우를 Gleo/기존 리마인더·경유지 기능과 비교한다. Gleo가 처리할 수 있으면 가설을 축소/기각한다. 사용자의 실제 입력 부담이 절감량보다 크면 별도 앱 이유도 약하다. 실차/계정 없이 현재 에뮬레이터만으로 완결 검증은 불가능하다.

### 후순위/제외

- 개인 목적지 진입·주차·챙길 물건 메모: 기본 주차 위치·도보 안내·리마인더와 겹치며, 반복 목적지는 이미 알고 신규 목적지는 기록이 없다는 약점. 독립 주력 추천 제외.
- 개인 학습 진행도·질문 이력 기반 청취: Gleo가 학습 앱을 호출하는 공존 구조는 가능하지만 픽클 어학과 모바일 학습 대체재가 있고, 주행 중 질의응답 인지 부담도 별도 검증 필요. 유망 공백으로 확정하지 않음.
- 단순 이어듣기/도착 요약, 경로상 맛집/주유·충전, 차량관리·연비점수, 범용 아침 브리핑: 기존 영역과 중복하여 현재 증거로 주력 추천하지 않음.

## Gleo와 함께 동작하는 구조의 실제 조건

공식 가이드는 앱 기능을 schema.json으로 기술하고 assets에 배치, action filter 정의, 검토·승인 후 통합 활성화를 설명한다. Callback은 success/asking/fail 및 결과를 반환하는 계약이다. [S18][S19] 따라서 “Gleo가 입구, 앱이 고유 서비스 상태/처리 담당”은 공식 구조에 맞는 설계 방향이다. schema 작성만으로 승인·인식·실행이 완료되지는 않는다. STT를 붙인 자체 음성 UI는 Gleo 연동 증거가 아니다.

## 새 아이디어 전환을 포함한 초기 탐색

사용자 후속 의견: “새로운 아이디어로 트는것도 나쁘지 않다고 생각해”. 대체 후보 조사 허용으로 반영하며 D-014 변경·기존 구현 폐기·새 구현 승인으로 처리하지 않는다. 아래는 Codex 초기 반례 탐색이며 앞선 Claude 검수에 포함되지 않았다.

- **함께 쓰는 차의 인수인계:** 앱이 사용 예약·차 상태·남겨둔 물건·미해결 문제와 확인 이력을 보관하고 Gleo는 입력/조회 역할을 맡는 가설. 그러나 마이현대는 이미 차량 기본정보와 카라이프/정비/충전 기능 공유를 설명한다. Kai는 가족/공동 소유 차량의 예약·주행계·연료·사진·문제 신고·인수인계 체크리스트를 소개한다. 기본 공유/인수인계를 신기능으로 추천할 수 없으며, 국내 실사용 마찰과 차량 맥락 자동화의 추가 가치가 남는 질문이다. [S30][S31]
- **반복 이상 증상→정비 전달:** 발생 조건과 사용자 관찰을 누적해 정비 방문 시 전달하는 가설. 현대 선제 케어는 주행 중 이상 징후 감지/알림을 제공하며 원격 수집 가능한 데이터의 한계를 명시한다.
