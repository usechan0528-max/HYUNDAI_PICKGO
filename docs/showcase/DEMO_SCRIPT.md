# PICKGO 공모전 시연 대본

- 형식: 1920×1080 MP4, 한국어 화면 설명, 무음.
- 촬영: 현재 웹 앱을 실제 Chrome에서 조작하고 운전자·모바일 크기 탑승자 화면을 함께 배치.
- 인물: 운전자와 동행 A·B·C 모두 가상. 실제 개인 위치·연락처 미사용.
- 편집: 준비·로딩 구간 일부 축약, 장면별 설명 추가. 별도 native 녹화는 촬영일과 환경 표시.
- 파일: [PICKGO_DEMO.mp4](video/PICKGO_DEMO.mp4).

## 장면 1 — 한 명과 만날 장소 정하기

- 상황: 퇴근 후 양재에서 동행을 태우려는 운전자.
- 첫 화면: “어디서 태울까요?”
- 조작: 하나로마트 검색 → 검색 결과 → 주변 후보.
- 메시지: 서로 만날 구체적인 픽업 장소부터 정리.
- 지도: 위치·차단 영역 확인. 현장 정차 가능 여부 확인 필요.
- 초대: 운전자가 만든 링크에 동행 참여.
- 준비: 동행이 준비 완료 → 운전자 화면 반영.

## 장면 2 — 변경을 서로 확인하기

- 상황: 동행이 현대자동차 양재사옥 쪽에서 만나기를 제안.
- 선택: 위치 공유는 거부하고 계속 진행.
- 조작: 탑승자 장소 변경 제안 → 운전자 수락.
- 메시지: 상대 수락 전에는 확정 장소가 바뀌지 않음.
- 주의: 고정 목록 장소 변경은 이름 기반 합의이며, 이 장면을 native 좌표 안내 성공으로 연결하지 않음.

## 장면 3 — 도착부터 탑승 완료까지

- 조작: 운전자 도착했어요 → 탑승자 탑승했어요 → 운전자 종료 확인.
- 메시지: 위치 추정이 아닌 양측의 명시적 확인.
- 결과: 한 번의 픽업 완료.

## 장면 4 — 세 명을 두 지점에서 태우기

- 상황: 동행 A는 첫 지점, B·C는 같은 두 번째 지점에서 승차.
- 조작: 출발 설정 → 사람별 초대 → B·C 공동 지점 지정 → 각자 참여·준비.
- 운전자: 다음 지점 선택 → 도착 표시.
- 탑승자: 사람별 탑승 확인.
- 메시지: 같은 지점에 남은 사람이 있으면 다음 지점 진행을 제한.
- 결과: 세 명 모두 탑승 완료.
- 범위: 수동 순서. 실제 도로시간 추천·현대 내비 다중 경유는 미연결.

## 장면 5 — 실제 NaviHelper 연결 증거

- 별도 촬영본: 2026-11-04 `reviewed-demo.mp4`의 실제 Pleos 에뮬레이터 화면 일부.
- 내용: OSM 확정 지점에서 native 안내 시작 → 현대 내비 경로 화면.
- 최신 웹 화면과 동일 회차·동일 빌드의 연속 장면으로 표현하지 않음.
- 목적지 일치·ROUTE_GUIDING·45초 결과 유지의 최신 재검증은 [2026-11-06 기록](../PICKGO_INTEGRATION_2026-11-06.md) 참조.
- 실차·물리 휴대폰·차량 주행 제한 검증 완료를 뜻하지 않음.
