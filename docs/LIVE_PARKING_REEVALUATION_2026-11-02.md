# 실제 데이터 연동 후 공동 재평가

2026-11-02 · Codex 구현/통합, Claude Haiku 5.5 독립 검수, Claude Opus 5.5 제품 평가.

## 판정

**현 주차 아이디어의 공모전 주력 개발을 종료한다. 실험 코드는 보존한다.** 사용자가 실제 연동·개선 후 발전 가능성이 작으면 폐기하고 새 아이디어를 구상하도록 지시한 범위의 판단이다. 주차 사업 전체가 불가능하다는 결론은 아니다.

공공 API 1곳 연결은 성공했다. 하지만 데이터 없는 사설 주차장의 여석을 추정한다는 핵심 가치는 입증하지 못했다. 초기 점유/비참여 유입을 알 수 없고 차량 움직임과 출차·빈자리 발생은 같지 않다. 운영자 로그 제휴나 충분한 관측 및 현장 진실값 확보가 대안인데, 현재 어느 것도 확보하지 못했다. 공공 주차장을 더 늘리는 것은 이 병목의 해결이 아니다.

## 실제 구현과 검증

- 서울시 GetParkingInfo 공개 sample에서 세종로 공영주차장 코드171721 선택. 실제 INFO-000 응답 → 서버 → 브라우저 표시 성공. 첫 응답 총1260면/차량110대. 현장 센서 정확도를 독립 실측한 결과는 아니다.
- `/live`는 실제 공공 데이터, `/`는 기존 합성 시연으로 분리. 개인키·위치·이용자 차량 수집 없음.
- 관측/수신시각·출처 표시, 5분 만료, 잘못된 시각/수치/대상 누락/네트워크 오류 시 수치 숨김. 요청8초/256KB 제한, 60초 캐시 및 중복 요청 통합. 고정 upstream/주차장만 조회.
- 총면−차량수 계산은 일반 여석이 아니다. 검수 후 계산값을 화면에서 제거했다. HTTP 공개 sample은 개발용이고 운영 연결이 아니다.
- `node --test mvp/*.test.js`: 최종 **22/22 통과**. 서버/도메인 및 클라이언트 fake DOM 경계 검증. 마지막 2개는 잠자기로 단조시계가 멈춘 상황, 벽시계 역행, visibility/mode 변경에 대한 회귀다. fake DOM은 실제 OS 잠자기나 CarUxRestrictions 검증이 아니다.
- 브라우저 실제 연결 표시·초기 제한·주행 제한 전환·최종 코드 재로딩 후 실제 숫자 표시 확인. 최종 화면 evidence/live-parking-final-2026-11-02.jpg.
- SDK, APK, 에뮬레이터, 실차, 현장 진실값, 사용자 이해도/수요, 사설 추정 정확도는 미실행. 공공 API HTTP 운영 보안은 미확보.

## Haiku 검수와 처리

실제 modelUsage `claude-haiku-5-5`, 같은 세션 2회. 도구 없이 소스 스냅샷을 읽었으며 실행 시험은 Codex 담당이다.

| 지적 | 처리 |
|---|---|
| P2 캐시 중 5분 경계가 지나도 API fresh | 응답 시 age/status 재계산, 5분 경계 회귀 통과 |
| P2 클라이언트 시계 오차 | 서버 age + 요청 시작 이후 경과 사용 |
| P2 계산 차이를 여석으로 오해 | 차이 숫자 UI 제거 |
| P2 수동 게이트를 보안처럼 오해 | 시연·SDK미연동·보안잠금아님 명시 |
| 후속 P2 잠자기 중 performance 경과 정지 | 제안대로 performance/벽시계 경과 중 큰 값 사용, visibility 변경 시 취소·데이터 폐기. Codex 회귀 2개 추가 통과. 이 마지막 수정은 Haiku의 수정안 적용이며 별도 세 번째 검수는 하지 않음 |
| P3 hidden CSS 문맥 누락 | 기존 display:none!important 존재, 실제 브라우저 제한 전환 확인 |
| P3 실패 캐시60초 | 공급자 요청 부담 제한 위해 유지, UI에 표시 |
| P3 pending 정리 경쟁 | 조기 return은 finally 진입 안 하므로 최초 요청만 정리. 근거 전달, Haiku 후속에서 수용 |
| P3 비정상 HTTP body | cancel 추가 |
| P3 성공200/헤더 시험 없음 | 추가 시험 통과 |
| P3 고정 이름/주소·KST·HEAD | 대상 이름/주소는 실제 첫 응답과 일치하는 정적 표기. 관측 KST는 요청 UTC+9와 1분 이내 일치 확인, 공급자 시간대 명시 확인은 남음. API HEAD405 의도된 정책 |

P0/P1은 전달한 범위에서 발견되지 않았다. 전체 안전성 인증이나 운영 승인으로 확대하지 않는다. timeout 실네트워크 강제 지연, OS 잠자기, 일부 HTTP 오류 분기는 별도 실증하지 않았다.

## 내부 재평가 (각100점, 공식 배점 아님)

| 항목 | Codex 이전 | Codex 현재 | Opus 이전 | Opus 현재 |
|---|---:|---:|---:|---:|
| 차량 특화성 |45|45|45|40|
| 창의성 |55|55|55|50|
| 기술 구현 |45|60|50|59|
| 사업성 |35|35|35|32|
| 단순 평균 |45|48.75|46.25|45.25|

두 평가자 평균은 이전45.625 → 현재47.0이다. 통계적 유의성이나 수상 확률을 의미하지 않는다. 기술 개선은 인정하되 새 공공 연동이 차량고유성/민영차별성/수요를 입증하지 못했다. Opus는 실제 구현의 공공조회 비중을 보고 나머지 항목을 더 보수적으로 재산정했다. Codex는 기존 가설 점수는 유지했다. 의견차를 숨기지 않고 점수를 억지로 합의하지 않았다. 내부 희망선 평균90·각70초과와는 여전히 큰 격차다.

Opus는 처음 기술57, 후속 수정·회귀 증거를 받고59로 변경했다. 이는 20개 시험 시점의 평가이며 최종22개 통과를 이유로 추가 가점하지 않았다. 두 호출의 modelUsage는 claude-opus-5-5다.

## 재개 조건

운영자 로그/계측 등으로 진실값 확보 후 시간 분할 홀드아웃, 시간대별 평가, 여석 있음 오판 비용, 단순 시간대 베이스라인을 사전에 정해 비교해야 한다. Opus 최초 제안의 30회/+15%p/2주는 검증된 기준이 아니어서 채택하지 않았다. '참여밀도만이 유일 경로' 단정도 운영자 제휴 경로를 반론하여 정정했다.

## 새 후보: 주행 후 승차감 리플레이

**가설:** 주행 중 조작 없이 급격한 속도·가속 변화 구간을 기록하고, 정차 후 동승자가 남긴 불편 기록과 대조해 다음 운행에서 바꿀 습관 하나를 보여준다. 여러 사용자의 데이터나 외부 주차 사업자 없이 한 차량·동승자 조합부터 검증할 수 있다는 구조적 장점이 있다. 효과가 입증됐다는 뜻은 아니다.

최소 흐름: 명시적 기록 동의 → 주행 중 수동 조작 없음 → 플랫폼이 허용하는 정차 상태에서 구간 최대3개 복기 → 동승자 사후 피드백 → 다음 운행 비교. 위치는 필수가 아니며 시간축 중심·로컬 짧은 보관을 우선한다. 자동 차량 제어·주행 중 코칭·멀미 진단/예방 주장은 제외한다.

가장 먼저 확인할 것: 공식 SDK에서 필요한 속도/가속도 또는 도출 가능한 신호의 심볼·권한·샘플링·기록 허용과 접근 환경. 최소 샘플 요구는 신호처리 가설과 함께 먼저 정해야 하며 아직 정하지 않았다. 문서에 신호가 있다고 실제 접근 가능하다고 간주하지 않는다. 확인 불가면 후보 보류.

사용자는 실차 이용 불가로 정정했다. 따라서 Opus가 처음 제안한 휴대폰10회주행/본인EV2주기록은 실행하지 않는다. '멀미지수' 명칭도 철회했다. 합성 시계열로 구현 흐름은 시험할 수 있지만 승차감 효과나 SDK 성공의 증거는 아니다. 실차·자발적 동승자 관측을 확보하기 전 효과 검증은 차단 상태다. 불편 유발 실험이나 주행 중 조작을 요구하지 않는다.

차별성 위험: 급변 구간과 실제 불편이 대응하지 않으면 흔한 운전 점수의 변형으로 끝난다. 일반 운전 점수보다 복기·행동 변화에 도움이 되는지 검증해야 한다. 신제품 점수는 아직 매기지 않는다. 현재는 **후보 제안**이며 새 앱 본개발 확정은 아니다. 두 번째 EV 다음 출발 충분성 후보도 본인 차량 데이터 부재와 기존 주행가능거리 기능 중복 때문에 보류한다.
