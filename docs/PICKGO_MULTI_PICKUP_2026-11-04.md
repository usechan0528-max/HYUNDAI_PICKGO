# PICKGO 다인 픽업 · 경유와 추천 순서

2026-11-04 KST. 사용자 요청: “픽업 할 사람이 여러 명일 때 경유 기능과 추천 픽업 순서 제안 기능까지 넣자”.

## 범위와 현재 상태

다인 픽업의 경유 기능과 추천 픽업 순서를 제품 범위에 추가한다. 아래 세부 동작과 수용 조건은 Codex 설계 제안이다. 이번 반영은 요구사항·설계 기록이며 실행 가능한 다인 기능 구현 완료가 아니다.

현재 `experiments/pickup-board/domain.mjs`는 회차당 rider/ready/joined/stage가 하나인 구조다. 초대 링크를 여러 명에게 그대로 재사용해서 해결할 수 없다. 기존 단일 픽업과 미커밋 변경을 보존하며 사람별 권한·상태, 경유 계획, 내비 연결을 함께 확장해야 한다.

## 사용자 흐름

1. 운전자가 픽업할 사람과 각 사람의 승차 지점을 추가한다. 각 사람에게 독립적인 참여 링크를 제공하고 준비·참여 상태를 관리한다.
2. 최종 목적지가 있으면 함께 지정한다. 없으면 마지막 픽업 지점까지의 계획임을 표시한다.
3. `추천 순서 보기`로 현재 위치 → 픽업 지점들 → 최종 목적지를 비교한다. 기존 순서와 추천 순서, 추천 이유, 데이터 기준 시각을 보여준다.
4. 운전자가 순서를 수동 수정하거나 추천을 적용한다. 추천을 계산하는 것만으로 합의 장소나 실제 내비 경로를 바꾸지 않는다.
5. 안내 중 차량에는 다음 픽업 대상·지점과 남은 인원 중심으로 표시한다. 전체 순서 편집은 플랫폼 주행 제한이 허용할 때만 제공한다.
6. 도착과 탑승을 사람별로 확인한다. 같은 지점의 두 사람 중 한 명만 탔다면 다른 사람까지 탑승 처리하지 않는다. 해당 지점 처리가 끝나면 운전자의 명시 동작으로 다음 지점 안내를 요청한다.

## 추천 기준

- 기본 제안은 실제 도로의 방향별 구간 이동시간 합을 비교하는 방식이다. 출발점과 최종 목적지를 고정하고 미탑승 대상만 정렬한다. 직선거리 순서를 최단 시간 경로로 표시하지 않는다.
- 이동시간은 공급자·관측 시각·유효기간·교통 반영 여부를 함께 보관한다. 예상 대기시간을 더하려면 명시된 준비 시각 등 근거가 있어야 한다. `준비 안 됨`만으로 임의의 대기 분을 만들지 않는다.
- 준비 상태와 사용자가 고정한 순서/시간 조건을 함께 보여준다. 미준비자를 자동 취소하거나 건너뛰지 않는다. 시간 조건을 만족할 수 없으면 충돌을 표시하고 사용자가 조정한다.
- 출발 위치 미확인, 경로 누락, 오래된 응답 또는 공급자 실패 시 시간 추천을 제공하지 않고 수동 순서를 유지한다. 합성 데이터 실험은 화면에 명시한다.
- 동점이면 현재 순서를 유지한다. 이미 탑승한 사람은 다시 경유 목록에 넣지 않는다. 진행 중인 다음 지점은 기본적으로 고정하며 변경은 운전자 확인이 필요하다.
- 추천은 입력 revision에 결합한다. 사람·장소·순서·탑승·출발 위치 기준이 바뀌면 이전 추천은 만료한다. 적용 시 서버에서 최신 상태를 다시 검사한다.
- 초기 인원 상한, 경로 공급자, 계산 방식과 시간 유효기간은 구현 전 확정할 항목이다. 차량 좌석 수나 SDK 경유지 한도를 추측해서 정하지 않는다.

## 상태와 권한

- `trip`: 운전자, 전체 revision, 최종 목적지, 활성 지점, 경유 순서, 종료 결과.
- `participant`: 독립 ID/초대/인증, 참여·준비·탑승·취소 상태, 개별 위치 공유 동의. 다른 사람의 상태를 변경할 수 없다.
- `stop`: 합의된 승차 좌표와 revision, 연결된 참가자 ID들, 도착 상태. 좌표가 가깝다는 이유만으로 반대편 도로나 서로 다른 진입 지점을 병합하지 않는다.
- `recommendation`: 기준 revision, 출발 위치 기준, 순서, 비교 근거, 공급자/시각/만료, 적용 여부.
- 탑승자에게는 본인의 승차 지점·순번·상태를 우선 제공한다. 다른 사람의 정확한 위치·연락처·초대 토큰을 공유하지 않는다. 기존 위치 동의를 다른 참가자 공개 동의로 확대하지 않는다.
- 장소 변경은 영향을 받는 참가자의 합의를 받는다. 순서 변경과 장소 변경을 구분한다. 같은 지점의 공동 승차 장소를 바꿀 때 한 사람의 수락으로 모두의 합의를 대체하지 않는다.
- 취소된 사람은 계획에서 제외하되 기록을 보존한다. 모든 대상이 탑승 또는 명시 취소로 정리되어야 회차를 종료할 수 있다. 일부 취소가 있으면 모두 픽업 성공으로 표시하지 않는다.

## 현대 내비 연결 검증

기존 `PICKGO_PUBLIC_NAV_API_2026-11-04.md`는 `requestRouteWithWaypoints`, `addWaypoint`, `removeWaypoint`를 문서상 연결점으로 기록한다. 이는 이번 기능의 실동작 검증이 아니다. 기존 단일 목적지 에뮬레이터 성공을 다중 경유 성공으로 확대하지 않는다.

후속 검증: 실제 SDK의 경유 계약·순서·한도, 경로 전체 조회/일치 확인, 중간 도착과 다음 안내, 재요청·취소·서비스 단절을 확인한다. 전체 경유가 지원되지 않는 환경에서는 다음 확정 지점 하나씩 전달하는 대안을 검토하되 다중 경유 연동 성공으로 표시하지 않는다. 순서 적용과 내비 경로 확인은 별도 상태로 관리하고 실패·불일치를 표시한다.

## 완료 조건

1. 서로 다른 3명의 초대·준비·도착·탑승이 독립적으로 동작하고 다른 참가자의 변경·개인정보 접근이 차단된다.
2. 출발점·최종 목적지·방향별 시간에 따라 추천 순서가 달라지는 시험과 동점·미준비·고정 순서 시험이 통과한다.
3. 추천 조회만으로 경로가 변경되지 않는다. 오래된 추천 적용, 중복 적용, 취소와 적용의 경합이 거부되거나 일관되게 처리된다.
4. 같은 지점의 여러 명, 중간 취소, 탑승 후 재추천, 위치 동의 거부, 경로 누락에서 사람이나 지점이 조용히 사라지지 않는다.
5. 실제 내비 경유 순서와 목적지를 확인한다. 미지원·불일치·시간 초과를 성공으로 표시하지 않는다. 합성 시험과 실제 SDK 증거를 분리한다.
6. 기존 1명 픽업 흐름의 회귀 검증 및 Claude 독립 검수·중요 지적 처리를 완료한다.
