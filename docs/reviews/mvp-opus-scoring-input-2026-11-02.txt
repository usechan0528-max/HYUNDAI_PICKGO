기준: 현재 구현과 확인된 증거만 인정. 미구현 미래 예측·사용자 수요·SDK 가능성을 성공으로 선반영 금지. 점수는 주관적 내부 판단이며 공식 심사점수/수상확률/개발완료율 아님. 5점 단위 사용. 90이상은 중대한 반대 근거가 해소된 강한 증거, 75~85는 핵심 가치/기술이 상당 부분 입증, 60~70은 구체 방향/일부 구현이나 주요 가설 미입증, 40~55는 부분 시연과 핵심 실현조건 미확인, 그 이하도 증거 부족에 따라 가능. 자체 목표 평균90이상·각항목70초과(공식 배점 아님). 가중치 없이 평균.

# 초기 MVP 공동 평가 — 도착 전에

평가일: 2026-11-02 KST. Codex 구현·실행 시험, Claude Haiku 5.5 소스 검수, Claude Opus 5.5 제품 평가. 판정은 **로컬 정보 표시 프로토타입 완료 / 제한 파일럿 준비 / 실제 서비스 출시·예측 개발 보류**다.

## 실행 결과와 평가 범위

합성 주차장 세 곳을 대상으로 후보 선택 → 정보 근거/현재성 구분 → 진입 안내 → 화면 이해도 피드백까지 연결했다. 공식 형식의 여석, 참여 관측, 정보 미연계를 구분한다. 실제 위치·SDK·공공 API·차량 이벤트·예측 모델은 연결하지 않았다. 따라서 사용자 제안의 핵심인 미연계 사설 주차장의 실제 현황 파악은 아직 입증하지 못했다.

- 실행: Node.js v25.9.0, `node mvp/server.mjs`, http://127.0.0.1:4173.
- 자동 시험: `cd mvp && node --test` 최종 종료 0, **13개 통과**. 도메인 11개, HTTP/서버 기동 2개.
- 브라우저: 초기 잠금, 정차 전환, 세 후보 표시, 민영 상세, 표본 부족, 0면, 만료, 단절, 복구 후 만료 유지, 주행 제한 시 상세 제거, 피드백과 후보 변경 후 초기화 확인. 최종 브라우저 콘솔 오류 조회 결과 0건.
- 시각 확인: 기본 데스크톱 브라우저 화면의 카드·상세 배치 확인. 모바일·차량 디스플레이·화면읽기 도구 시험은 미실행.
- 외부 제출·배포·사용자 모집·실제 위치 수집은 하지 않았다. APK 없음.

## Haiku 구현 검수와 반영

첫 검수는 고정 스냅샷을 읽고 중요한 재현 가능 결함은 찾지 못했다고 보고했다. 실행 시험을 직접 한 것은 아니다.

| 지적 | 처리와 증거 |
|---|---|
| DOM 수준 잠금 회귀 시험 공백 | 브라우저에서 상세 비움·workspace 숨김 등 실제 확인을 기록. 자동 DOM 회귀 시험은 아직 없음 |
| 공백/한글 경로에서 서버 기동 가드 불일치 | `pathToFileURL` 적용 후 실제 임시 경로 기동 시험 추가. 첫 시험에서 심볼릭 링크 정규 경로 차이를 발견, `realpathSync`까지 적용 후 통과 |
| 자정 표시의 24시 표현 가능성 | `hourCycle: 'h23'`로 수정. 전 시간대/브라우저 조합 검증은 미실행 |

Haiku가 언급한 기존 저장소 삭제/수정 상태는 이번 검수 입력 범위 밖이다. 이번 검수 성공을 기존 변경 전체의 검수로 확대하지 않는다.

수정 후 같은 Haiku 5.5 세션에 재검수를 요청했고 새 중요 결함은 보이지 않는다는 답변을 받았다. 추가 낮은 우선순위 지적은 다음처럼 처리했다.

- 경로 기동 시험의 stdout 청크 분할·실제 응답 미확인: 해당 시험은 진입 가드의 실제 프로세스 기동 회귀를 겨냥했고 HTTP 제공은 별도 시험에서 확인했다. 전체 테스트를 배포 검증으로 확대하지 않는다. 줄 단위 준비 신호와 동적 포트 출력 보강은 후속 개선으로 남긴다.
- 존재하지 않는 argv 경로의 realpath 예외: 현재 문서화한 직접 실행과 테스트에서는 존재하는 경로를 사용한다. 일반 기동 실패 처리 개선 항목으로 남긴다.
- 후보 클릭·피드백 미확인: 후속 입력 작성 뒤 브라우저 확인을 완료했고 전환 시 피드백 초기화를 확인했다.
- 자정 브라우저·자동 DOM 시험: 미실행 상태를 유지한다. 코드 변경만으로 해당 환경 검증 완료라고 쓰지 않는다.

## Opus와 공동 제품 평가

| 평가 축 | 현재 근거 | 아직 입증하지 못한 것 |
|---|---|---|
| 차량 특화성 | 운행 제한 시 정보 차단, 도착 진입 정보 연결 | 차량 데이터 실제 수급, 휴대전화 대비 우위 |
| 창의성 | 미연계 사설 영역으로 확장하는 가설, 근거별 표시 | 기존 서비스와 비교한 실제 추가 가치 |
| 기술 활용성 | 표본·동의·귀속·시각 검사와 실패 상태 처리 | 실차 센서·SDK·예측 성능 |
| 사업성 | 공공 현황으로 초기 이용가치를 제공할 가능성 | 사용자 밀도·재사용·지불 주체·운영사 참여 동기 |

수치 점수로 준비 수준을 과장하지 않고 미확인 조건을 유지한다. 기존 공모전 자체 통과 기준(평균 90 이상, 전 항목 70 초과)을 충족했다고 판단할 증거는 없다.

가장 큰 위험은 (1) 사설 주차장별 참여 차량 부족, (2) '움직임 관측'이 쓸모 없거나 빈자리로 오해되는 문제, (3) 백그라운드 차량 신호 수집 가능성 미검증이다. 숫자를 표시하지 않아도 사용자가 빈자리가 생겼다고 추측할 수 있다.

Opus 1차 제안의 '부분 관측 언급/확신 증가' 성공 기준에 Codex가 반대했다. 선택이 바뀌었다는 것만으로 더 나은 선택이 되지는 않는다. 또한 움직임 관측을 점유/출차 라벨과 바로 대조하는 것은 다른 사건을 비교하는 오류다. Opus는 두 반론을 수용하고 근거 없이 제안한 20% 오해·30% 표본 충족 기준을 철회했다. 현재 5명/5분 시연 정책은 개인정보 보호나 예측 유효성이 입증된 기준이 아니다.

## 다음 단일 실험: 해석 오류 확인

이 MVP로 먼저 알아볼 질문은 **'참여 차량 움직임을 본 사람이 빈자리 또는 출차를 확정된 사실로 오해하는가?'**다. 5~8명 규모 탐색을 제안하며 아직 참가자를 모집하거나 실험하지 않았다.

1. 설명을 먼저 가르치지 않고 합성 후보 화면을 보여준다. '각 주차장의 빈자리 수에 대해 무엇을 알 수 있나요?', '민영 관측 문구는 무엇을 의미하나요?', '출차가 확정됐나요?'를 묻는다.
2. 공식 현황만 제공한 버전과 참여 관측을 함께 제공한 버전을 비교한다. 최초 해석을 기록하기 전에 다른 조건을 보여주지 않고, 조건별 참여자 또는 동등 난이도 다른 사례를 배정한다. 버전별 차이 분석은 표본이 작아 탐색 수준에 한정한다.
3. 기록: 최초 답변, 사실/추정 구분, 선택 이유, 근거 없는 확신 증가, 설명 후 재진술. 앱 피드백 버튼은 자료를 저장하지 않으므로 평가자는 동의 범위에서 별도 비식별 기록한다.
4. 빈자리/출차로 단정하거나 근거 없이 확신이 커진 사례가 한 건이라도 있으면 표현·정보 구조를 수정하고 새 참여자로 재시험한다. 이는 내부 수정 기준이지 안전성 통계 입증이 아니다.
5. 단정 사례가 없더라도 효용·수요 통과로 보지 않는다. 화면 의미를 정확히 이해할 수 있는지 확인한 뒤 단일 시설의 실제 사건 라벨 확보 가능성을 검토한다.

후속 실측에서는 차량 사건 인식과 여석/출차 예측을 별도로 평가한다. 참여율·정보 표시 가능 시간·오탐/누락을 먼저 측정하고, 공식값만 사용하는 기준보다 추가 관측이 올바른 판단에 기여하는지 확인한다. 이 자료 없이 예측·추천 기능을 확대하지 않는다.
