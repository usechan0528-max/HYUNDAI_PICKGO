# 한 화면 중심 픽업 UI 후속

사용자 승인: 후보 대신 문맥에 맞는 장소 표현, 버튼 기능명 축약, 좌표 표시 제거, 개발용 설명 숨김, 필요한 요소만 한 화면에 배치. main 기존 미커밋 보존.

## 변경

- 메인·지도·추천·다인 화면과 관련 오류 문구의 `후보`를 `장소`로 정리. 버튼은 돌아가기/새로고침/여기서 픽업/장소 제안 등으로 축약.
- 장소·준비 상태·주요 행동을 기본 화면에 유지. 위치 링크·기록·종료·새로고침은 `픽업 관리`에서 펼친다. 연결 실패와 종료 상태에서는 관리 메뉴를 상태 전환당 한 번 열어 복구/새 픽업을 노출한다. 폴링으로 사용자의 접기 선택을 되돌리지 않는다.
- 검색 장소 선택 후 검색 결과는 접히며 다시 펼쳐 다른 결과 선택 가능. 지도 설정과 주변 장소를 접고 지도·선택한 장소·확인 버튼을 먼저 보여 준다.
- 모바일 주요 조작은 56px 이상을 유지하며 필수 정보와 문구 크기를 줄여 억지로 채우지 않는다. 아주 작은 창·확대·오류 메시지·관리 메뉴를 펼친 상태는 스크롤을 허용해 내용을 잘라내지 않는다.
- 지도 위경도와 다인 초대/목적지 좌표를 화면에서 제거. 지도 선택과 서버 전송 좌표는 유지한다. `지도 핀` 대신 `선택한 장소`.
- 사용자 추가 요청에 따라 개발용 시연 링크, SDK/검증 설명, 합성 데이터 조작 및 개발 설정은 숨김. 위치 수집 동의·오류·실제 정차 안내는 유지. 숨김은 실제 SDK 연결이나 합성 데이터를 실제 데이터로 바꾸는 처리가 아니다.
- domain/recommendation board는 오류 문자열만 변경, 상태 규칙/API는 변경하지 않음. 기존 다른 작업자의 다인 로직과 시험 변경 보존.

## 검수

실제 Claude Haiku5.5 session fb735dc7-7ae6-43a4-a0b4-a9cf3a2f9245, exit0/is_error false. 읽기 검수, 실행 검증과 구분.

- 메뉴 반복 자동 열기 지적 반영: 상태 전환당 1회.
- 종료/새로고침 메뉴 발견성: `픽업 관리`로 명시하고 종료/오프라인 자동 노출 유지. 평상시 접기는 사용자 요청에 따른 점진적 노출.
- 초대 미리보기 오해: `초대 링크 열기`로 수정.
- 지도에서 제안 대신 시작할 수 있다는 지적: updateAction의 session 조건이 실제로 제안/생성을 구분하므로 해당 코드 확인 후 미반영.
- 검색 결과 kind 누락 구분자와 `목록를` 오타 수정. 접힌 결과를 펼치라는 복구 문구 반영.
- 준비 중 버튼은 상태 선택 토글이며 aria-pressed를 유지한다. 지도 직접 선택은 검색 결과를 선택한 뒤 homeCandidates가 열리는 범위에서만 노출되므로 선행 장소 없음 지적은 해당 없음.
- 운전자 화면의 위치 공유 제목은 `픽업 위치 공유`로 중립화.
