# 추천 개발안: 차량 기능 길잡이

2026-11-02 KST. Codex–Claude 실제 2회 왕복 회의 결과. 제품 성공 판정이 아닌 조건부 검증 개발안이다. 이번 요청의 산출물은 추천안과 최소 범위 정리이며 구현은 아직 하지 않았다.

## 추천과 이유

차량 기능에 익숙하지 않은 운전자가 출발 전·주차 후 불편 한 가지를 선택하면, 자신의 차종·연식·사양에 맞는 공식 근거와 짧은 조작 안내를 받는다. 핵심 가설은 기능 이름을 몰라도 불편에서 출발하면 설명서에서 올바른 조작법을 찾는 부담이 줄어든다는 것이다. 실제 부담 감소·수요·반복 사용성은 미검증이다.

| 후보 | 회의 결론 | 이유 |
|---|---|---|
| 공동 경유 변경·취소 | 보류 | 원래 지식 공백 문제와 거리가 있고 기본 내비 대비 가치·실제 반영 계약 미검증 |
| 상황별 차량 기능 안내 | 조건부 검증 개발 추천 | 원래 목표와 가장 가까우며 직접 제어 없이 내용·흐름 검증 가능 |
| 가족 준비 항목 인계 | 보류 | 공유 메모 대비 차량 특화성 미입증 |

Codex는 처음 경유 요청 관리를 선호했으나 Claude의 목표 이탈 지적을 수용했다. Claude도 fake로 경유 요청의 앱 내부 정합성을 시험할 수 있다는 Codex의 정정을 수용했다. 단, 실제 내비 반영이나 제품 효용을 입증하지는 않는다.

## 최소 범위

- 대상: 해당 기능을 잘 모르는 운전자 한 유형.
- 콘텐츠: 한 차종·연식·사양 조합과 불편 한 가지. 구체 기능은 아래 선정 기준을 통과한 뒤 정한다.
- 흐름: 사양·불편 선택 → 문서상 지원 여부와 근거 → 조작 안내 → 도움됨/해결 안됨.
- 화면: 선택 화면, 근거·안내 화면, 결과 화면 3개. 해결 안됨에는 공식 설명서 원문으로 돌아갈 경로를 둔다.
- 지원 상태: 문서상 지원 / 문서상 명시적 미지원 / 확인 불가. 문서 미기재는 미지원으로 처리하지 않는다. 사용자 선택 정보에 따른 문서 판정이며 실제 차량 진단으로 표시하지 않는다.
- 안내: 공식 경로의 실제 조작이 최대 3단계인 기능만 채택한다. 의미를 보존해 작성하며 단계 병합·생략으로 상한을 맞추지 않는다. 필요한 사전 조건과 주의사항도 유지한다.
- 데이터: 출처 URL, 문서 위치, 적용 사양, 확인일을 콘텐츠마다 보관한다. 검증용 피드백은 로컬 최소 항목만 저장하고 삭제 기능을 둔다.
- 제외: 직접 차량 제어, 생성형 답변, 음성, 가입·서버, 다중 사용자 조율, 차량 전체 기능 확장.

첫 기능 선정 조건은 (1) 대상 운전자가 실제로 겪은 어려움의 사례, (2) 운전자가 직접 조작하는 기능, (3) 적용 사양과 조작 경로가 명확한 공식 문서, (4) 정확성과 주의사항을 유지하는 3단계 이내 안내다. 후석 휴식 예시는 근거를 확보하기 전 첫 항목으로 채택하지 않는다. 실제 사례 확보와 참가자 모집은 미실행이다.

## 개발 순서와 플랫폼 제한

1. 첫 기능의 공식 근거와 실제 어려움 사례를 확보하고 콘텐츠를 고정한다. 통과하지 못하면 제품 콘텐츠 구현을 보류한다.
2. 로컬 시연으로 선택·지원 판정·안내·오류·피드백 흐름을 만든다. 전 화면에 시연임을 표시하고 모의 상태를 실제 주차 판정처럼 표현하지 않는다.
3. Codex가 상태 모델과 경계 조건을 검증하고, Claude는 고정 diff와 실행 증거를 읽어 독립 검수한다.
4. Android/Pleos SDK와 플랫폼 UX 제약을 확보·검증한 뒤 실제 어댑터를 붙인다. 정확한 심볼과 버전은 실제 선언 대조 전 확정하지 않는다.

실제 앱은 검증된 플랫폼 UX 제약을 따라야 한다. 주행 제한·상태 미확인·단절 시 상세 안내와 입력을 차단한다. 속도 0이나 사용자의 주차 버튼을 허용 근거로 쓰지 않는다. 시연용 상태 주입은 실제 앱의 제한을 해제하지 않는다. 현재 SDK 빌드·에뮬레이터·실차 시험 모두 미실행이다.

## 수용 조건

- 사양·근거가 맞지 않으면 확인 불가. 문서가 없는 기능을 지원 또는 미지원으로 단정하는 사례 0건.
- 선택 사양을 변경하면 이전 지원 판정과 안내를 즉시 제거한다.
- unknown·단절·주행 제한 전환 시 입력과 상세 안내를 차단한다. 시연 통과와 실제 플랫폼 통과를 별도 기록한다.
- 조작 단계·사전 조건·주의사항이 공식 문서와 일치한다.
- 해결 안됨에서 원문 안내로 돌아갈 수 있고 로컬 피드백을 삭제할 수 있다.
- 데모 데이터와 실제 SDK 데이터가 명확히 구별된다. API 요청 수락을 실행 완료로 표시하지 않는다.

## 효용 검증과 중단 조건

5명 규모의 탐색 시험을 제안한다. 해당 기능을 써본 적 없는 사람을 사전 질문으로 선별하고 정지 환경에서 수행한다. 같은 과업을 두 번 수행시키는 학습 효과를 피하려면 참가자별 한 조건만 배정한다. 표본이 작으므로 조건별 원자료를 보고하며 통계적 우위는 주장하지 않는다. 더 큰 비교 시험에서는 동등 난이도 과업을 확보한 뒤 교차 설계를 검토한다.

내부 진행 기준 제안: 5명 중 4명 이상이 올바른 조작 경로에 도달하고 잘못된 지원 안내는 0건. 조건별 성공률·전체 소요시간·막힌 지점을 보고한다. 이 수치는 성과나 통계적 유의성의 증거가 아니다. 유리한 비교 증거가 없으면 설명서 대비 우위 주장도 보류한다. 실제 Gleo 비교는 미실행이며 비중복을 확정하지 않는다. 시연 피드백은 실제 재사용·시장 수요 근거로 쓰지 않는다.

공식 근거를 확보하지 못하거나 실제 어려움 사례가 없으면 첫 기능을 채택하지 않는다. 기존 설명서보다 유리하지 않거나 기존 음성 도우미로 충분히 해결되면 차별화 주장을 철회하고 재평가한다. 새로운 기능을 계속 추가해 이 결함을 가리지 않는다.
