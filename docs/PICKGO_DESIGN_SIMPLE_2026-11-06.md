# PICKGO 화면과 문구 정리

2026-11-06 · main · 기존 미커밋 변경 보존. 사용자 요청: Claude와 디자인 협의, 안내 축소, 확정 체크, 픽업 개념에 맞는 구체적인 문구. API/도메인/Android 변경 없음.

## 결과

- 기존 Asta 글꼴과 어두운 평면 UI 유지. 장소 옆 초록 SVG 체크와 `장소 확정` 표시. 서버 최신 상태·진행 중·상대 참여·변경제안 없음에서만 표시한다. 준비/탑승 완료와 구별한다.
- 반복 설명 제거, 보조 링크 축소, 변경 기록 접기. 스크린리더 결과 알림은 접힌 기록 밖이자 화면 전환 section 밖에 별도로 유지한다.
- 메인/지도/위치공유/근접시연/추천/다인 화면 문구를 픽업 대상과 행동으로 구체화했다. `참여 대기`→`탑승자 참여 대기`, `회차 만들기`→`여러 명 픽업 시작`, `한 번만 공유할까요?`→`운전자에게 내 위치를 보낼까요?`.
- 개인정보 동의, 연결 실패, 현장 정차 확인, 합성 데이터 한계는 유지한다. 추천 후보 설명은 합성 지도상의 제외 조건임을 명시한다.

## 협의와 검수

기존 작업 폴더의 실제 Opus 5.5 협의(session 68b3ad79-97c1-4932-b93c-3842652f11d5)를 회수하여 이어서 작업했다. 상대 참여 전 체크 오해, stale/종료 상태 숨김, 장소변경 수락규칙 유지 의견 반영.

최종 실제 Haiku 5.5 읽기검수 session 92781f43-d966-434e-99e3-3ce08244cc18, exit 0 / is_error false. 소스 수정·도구 실행 없는 검수.

- 기존 hidden 우려: 전역 `[hidden]{display:none!important}` 확인, 브라우저 실제 숨김 검증으로 해소.
- 확정 조건의 joined 반대: Opus의 사용자 합의 해석을 채택. 저장만으로 확정 표시하지 않는다.
- 접힌 기록 알림: 별도 live region을 main 직속으로 이동하여 해소.
- 추천 실제 금지구역 판정 오해: 합성 데이터 한계를 첫 문장에 명시하여 수정.
- 초대 새 탭 sessionStorage 복제 우려: 링크에 `rel="noopener noreferrer"`가 실제 존재하며 브라우저 새 탭 참여 검증 통과. 참여 불가 링크로 바꾸라는 제안은 미반영.
- 다인 도착 감지 오해: `이 지점에 도착했어요`로 수동 사용자 행동을 명시.
- 추천 수락 검증 절차 부재 우려: recommendation/page.mjs 및 기존 accept 검증 흐름이 실제 최신 근거를 다시 확인하므로 미반영.
- 초대 유실 복구와 취소 권한은 기존 테스트로 검증되는 범위이며 디자인 변경으로 정책을 바꾸지 않았다.
- 6명 제한 반복 문구 축약, 취소 포함 제한은 보존. 문구 검사 테스트는 새 구체적 라벨로 갱신하며 상태 검증을 제거하지 않았다.

## 시각 검토

기존 true-black-flat 계열 화면을 유지하는 구성요소 수정으로 새 스타일 추첨 없음. 핵심 질문은 어디서 태우는지, 상대가 준비했는지, 다음에 누를 행동이 무엇인지다. 체크만 초록색으로 강조하고 사진·장식·진입 애니메이션을 추가하지 않았다. 합성 브라우저 시험 인물/장소 상태는 실사용 기록이 아니다.

1440/768/390: 제목과 행동 우선순위, 좌우 정렬, 체크 라벨 대비와 줄바꿈 확인. 휴대폰은 세로 스크롤 유지. 큰 차량용 터치 영역 때문에 데스크톱 행동 패널의 여백은 남아 있다. 정량 차트/합계/범례 해당 없음. 수치 기반 디자인 평점은 주장하지 않는다.
