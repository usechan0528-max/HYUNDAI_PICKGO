# PICKGO

**만날 장소부터 모두의 탑승까지, 함께 확인하는 픽업 약속판.**

- 운전자와 탑승자가 장소·준비·도착·탑승을 한 회차에서 공유.
- 한 명 픽업부터 여러 명의 공동 승차·지점별 진행까지 지원.
- 공모전 시연 자료: 실제 웹 앱 화면, 가상 사용 흐름, 별도 현대 내비 연동 증거.

[시연 영상 보기](docs/showcase/video/PICKGO_DEMO.mp4) · [전체 사용 설명서](docs/showcase/USER_GUIDE.md) · [시연 대본](docs/showcase/DEMO_SCRIPT.md) · [검증·촬영 정보](docs/showcase/VERIFICATION.md)

![PICKGO 운전자와 탑승자 화면](docs/showcase/screenshots/00-overview.jpg)

> 현재 단계: **로컬 웹 프로토타입 + 별도 Android 내비 연동 시연 앱**. 아래 최신 웹 화면은 2026-11-06 작업 트리에서 촬영했습니다. 모바일 화면은 같은 PC의 모바일 크기 Chrome입니다. 실제 차량·공개 서비스·물리 휴대폰 연동 완료를 뜻하지 않습니다.

## 화면으로 보는 사용 흐름

### 01. 어디서 태울지 검색하고 선택

- `하나로마트` 등 장소 이름 검색.
- 양재 주변 OSM 수록 장소에서 검색 결과·주변 픽업 후보 확인.
- 후보를 선택하거나 지도에서 직접 지점 지정.
- 일부 차단 영역을 표시하며, 정차 가능 여부는 현장 확인 필요.

- 운전자: 픽업 생성 → 초대 링크 복사 → 직접 전달.
- 탑승자: 링크 열기 → 참여 → 준비 완료.
- 상대 참여·최신 상태 확인 후 장소 확정 표시.
- 위치 공유는 선택. 공유하지 않아도 기본 흐름 이용 가능.

### 04. 도착·탑승을 확인하고 종료

- 운전자: `도착했어요`.
- 탑승자: `탑승했어요`.
- 실수한 도착·탑승 표시 취소 지원.
- 운전자: 종료 확인 → 픽업 완료.
- 탑승 전 종료는 취소로 구분. 위치로 자동 완료하지 않음.

![도착 확인](docs/showcase/screenshots/13-arrival.png)

### 05. 여러 명도 지점별로 진행

- 사람별 이름·지점·독립 초대 링크 관리.
- 같은 지점 함께 승차 지원.
- 순서 수동 편집 → 다음 지점 선택 → 도착 → 사람별 탑승 확인.
- 같은 지점의 모든 사람이 탑승·취소되어야 다음 지점 진행.
- 모두 탑승 / 일부 탑승·일부 취소 / 모두 취소 결과 구분.
- 회차당 취소 인원을 포함해 총 6명. 실제 차량 정원 준수 필요.

![여러 명의 준비 상태와 픽업 순서](docs/showcase/screenshots/19-multi-ready.png)

### 06. 확정 좌표로 현대 내비 안내 시작

- 별도 Android 앱의 명시적 native 버튼에서 NaviHelper 3.0.5 호출.
- 단일 회차의 OSM 확정 좌표·역할·최신 합의 상태 재검증.
- Pleos 에뮬레이터에서 목적지 일치·안내 중 상태·45초 결과 유지 확인.
- 다인 픽업의 현대 내비 다중 경유는 미연결.
- 아래 화면은 **별도 2026-11-06 통합 검증** 자료. 최신 웹 디자인과 동일 빌드의 연속 촬영본은 아님.

## 실행과 테스트

### 웹 시연

```sh
npm start
```

- 접속: `http://127.0.0.1:4180`.
- 운전자에서 초대 생성 → 같은 PC의 별도 탭에서 탑승자로 참여.
- 외부 API 키 없이 로컬 검색·픽업 가능. 배경 지도 타일은 인터넷 연결 필요.
- 서버 재시작 시 회차 소실. 기본 회차 최대 24시간, 지속 저장 아님.
- 다른 휴대폰 접속에는 별도 HTTPS·접속 구성 필요.

```sh
npm test
```

- 이번 실행: 웹 자동시험 **259/259 통과**.
- 실제 Chrome 시연: 단일 픽업 완료, 다인 3명·2지점·공동 승차·전체 완료 확인.
- 별도 이전 내비 검증: RouteGate 43 assertions, debug 빌드·lint, 에뮬레이터 목적지 일치·안내 확인. 이번 촬영에서 APK를 재빌드·재검증한 것은 아님.
- [검증 정보·재현](docs/showcase/VERIFICATION.md) · [상세 개발 실행 안내](experiments/pickup-board/README.md).

### APK 위치와 제출 상태

- 현재 로컬 debug APK: `experiments/pickgo-navigation/app/build/outputs/apk/debug/app-debug.apk`.
- build 폴더는 Git 제외 대상. 저장소 복제만으로 APK가 내려오지 않음.
- 실행 환경·SDK·기존 debug 키 요구사항: [Android 안내](experiments/pickgo-navigation/README.md).
- 공모전 제출용 release APK 및 `apk/` 제출 경로는 아직 준비·검증되지 않음.
- 웹 시연은 실제 SDK 연동을 요구하지 않으며, native 안내 시연은 Pleos 환경·NaviHelper가 필요.

# PICKGO 사용 설명서

- 목적: 운전자와 탑승자가 만날 장소·준비·도착·탑승 상태를 같은 픽업 회차에서 확인.
- 기준: 2026-11-06 작업 트리의 로컬 웹 프로토타입.
- 화면: 실제 Chrome 실행 캡처. 가상 인물만 사용. 휴대폰 모양 화면은 모바일 크기의 브라우저이며 물리 휴대폰 검증 자료가 아님.
- 조작: 주차 등 조작 가능한 상황에서만 시연. 현재 앱은 차량 주행 제한 연동을 완료한 배포본이 아님.
- 바로가기: [화면 중심 README](../../README.md) · [시연 영상](video/PICKGO_DEMO.mp4) · [시연 대본](DEMO_SCRIPT.md).

## 1. 시작하기

- Node.js 22 이상 설치.
- 저장소 루트에서 `npm start` 실행.
- 같은 컴퓨터의 브라우저에서 `http://127.0.0.1:4180` 열기.
- 운전자 화면과 탑승자 화면을 별도 탭으로 사용.
- 기본 주소는 같은 컴퓨터 전용. 링크를 다른 휴대폰으로 보내는 것만으로 접속되지 않음.
- 서버는 메모리 저장 방식. 재시작하면 회차가 사라짐.

![첫 화면](screenshots/01-home.png)

## 2. 한 명 픽업하기

### 장소 검색·선택

- 검색창에 장소 이름 입력 → 검색 버튼.
- 검색 결과 선택 → 주변 픽업 후보 확인.
- 후보 선택 → 픽업 시작 버튼.
- 현재 양재 주변에 수록된 OSM 장소·도로·주소 검색 지원.
- 전국 실시간 POI 검색 또는 실제 차량 현재 위치 검색은 미지원.
- 예시 검색어: `하나로마트`.

### 지도에서 직접 선택

- 검색 결과를 고른 뒤 `지도에서 선택` 열기.
- 지도 클릭 또는 `주변 장소·지도 설정`의 후보 선택.
- 선택 결과 확인 → `여기서 픽업`.
- 이미 참여한 회차라면 새 지점은 장소 변경 제안으로 처리.
- 지도 확대·축소, 검색 장소로 이동, 차단 영역 표시 전환 제공.
- 데이터에서 판별한 버스정류장·횡단보도 주변, 건물 내부, 고속도로·전용 차로 등 일부 영역 차단.
- 선택 가능 표시는 합법 정차 인증이 아님. 미수록 표지·시간대 통제 등이 있을 수 있으므로 현장 확인 필요.
- 지도 데이터는 유효기간 검사 대상. 만료 시 갱신 필요 안내.

- 같은 PC 시연: `초대 링크 열기`로 탑승자 탭 열기.

### 장소 변경·수락·거절·철회

- 운전자 또는 탑승자: `장소 변경 제안` → 다른 장소 선택.
- 상대: `이 장소로 변경`으로 수락 / `현재 장소 유지`로 거절.
- 제안자: 상대가 결정하기 전에 `제안 철회` 가능.
- 상대 수락 전까지 기존 확정 장소 유지.
- 수락 시 새 장소로 변경. 기존 도착 표시와 위치 공유 등 관련 상태는 새 장소 기준으로 재확인.
- 지도에서 선택한 지점과 고정 목록의 장소 변경은 구별. 고정 목록의 이름만으로 내비 전달용 확정 좌표가 확보되는 것은 아님.

### 도착·탑승·종료

- 운전자: 실제 도착 후 `도착했어요`.
- 탑승자: 실제 탑승 후 `탑승했어요`.
- 잘못 누른 경우 해당 역할의 `도착 표시 취소` / `탑승 확인 취소` 사용.
- 운전자: `픽업 관리` → `픽업 종료` → 종료 확인.
- 탑승 확인 후 종료는 완료, 탑승 전 종료는 취소로 구분.
- 종료 후 `새 픽업 시작`으로 새 회차 생성.
- `픽업 관리`에서 최근 변경 기록·새로고침·지도·위치 공유 접근.
- 도착·탑승은 수동 확인. GPS 근접만으로 자동 완료하지 않음.

## 3. 휴대폰 위치 공유 선택하기

- 탑승자: 참여한 탭의 `픽업 관리` → `휴대폰 위치 공유`.
- 목적·보관·삭제 안내 확인.
- `동의하고 현재 위치 한 번 공유`: 브라우저 위치 권한을 요청해 일회 공유.
- `동의하지 않음`: 위치를 보내지 않고 기본 픽업 기능 이용.
- `공유 중지 · 위치 삭제`: 서버에 중지·삭제 요청.
- 마지막 위치 1개만 보관. 관측 후 30초에 조회 차단, 다음 정리 주기에 제거.
- 공유 중지·탑승·종료 등 서버가 처리한 삭제 조건에서 제거. 단절 중 삭제 요청 도착은 보장되지 않으며 조회 만료 적용.
- 위치 공유는 도착·탑승 자동 확인에 사용하지 않음.
- 이번 영상은 동의 거부 흐름을 시연. 실제 휴대폰 HTTPS 위치 공유 성공을 증명하지 않음.

## 4. 여러 명 함께 픽업하기

### 회차·탑승자 추가

- 첫 화면의 `여러 명 함께 픽업` 선택.
- 출발 지점, 선택적 최종 목적지 선택 → `여러 명 픽업 시작`.
- 표시 이름·승차 지점 입력 → `초대 링크 만들기`.
- 사람별 독립 링크 제공. 각자 본인의 링크로 참여.
- 같은 장소에서 함께 탈 경우 `같은 지점 함께 승차` 항목을 명시 선택.
- 가까운 지점을 자동 병합하지 않음.
- 한 회차에 취소한 사람까지 총 6명. 차량 정원은 별도로 준수.
- 초대 후 장소를 바꾸려면 해당 사람을 취소하고 새로 추가. 공동 장소 재합의는 미지원.

### 순서·준비·탑승

- 탑승자: `이 지점으로 참여` → `준비 완료` / `아직 준비 중`.

## 5. 현대 내비 안내 시작 — 별도 Android 시연 앱

- 웹 브라우저의 기능이 아닌 별도 Android WebView 앱 기능.
- OSM 지도 좌표로 만든 단일 픽업 회차에서 탑승자 참여·장소 확정.
- 운전자 native 버튼 `확정 지점으로 현대 내비 안내 시작` 선택.
- 최신 회차·확정 좌표·역할·변경 제안 유무를 재검증한 뒤 NaviHelper로 목적지 전달.
- 에뮬레이터에서 현대 내비 목적지 일치·안내 중 상태 관찰.
- 안내 결과를 45초 관찰하고 복귀 시 마지막 관찰 결과 표시.
- 기존 내비 경로가 바뀔 수 있음. 안내 시작은 사용자의 명시 선택으로만 수행.
- 최신 웹 디자인 캡처와 별도 시점의 native 연동 증거를 구분. 동일 최종 제출 빌드의 연속 촬영본은 아님.

## 7. 연결 문제·복구

- 연결 실패·오래된 데이터: 현재 미확인 표시, 변경 동작 제한. 연결 복구 후 새로고침.
- 동시에 상대가 상태를 바꾼 경우: 최신 상태를 다시 확인한 뒤 재선택.
- 서버 재시작·회차 만료: 운전자는 새 회차 생성, 탑승자는 새 초대 수신.
- 초대 참여 재시도: 같은 브라우저에서 제한된 복원 지원. 다른 브라우저로 자동 이전되지 않음.
- 기본 서버의 회차는 최대 24시간, 메모리 저장. 영구 보관·회원 계정·운영용 복구 서비스가 아님.
- 지도 배경: 외부 OSM 타일 연결 필요. 로컬 장소 검색 데이터와 배경 지도 네트워크 의존성을 구분.
- 실제 배포 전 남은 작업: 공개 HTTPS·물리폰 전체 흐름·차량 UX 제한·실차·실제 경로시간·다중 경유·release APK 검증.

## 장면 1 — 한 명과 만날 장소 정하기

- 상황: 퇴근 후 양재에서 동행을 태우려는 운전자.
- 첫 화면: “어디서 태울까요?”
- 조작: 하나로마트 검색 → 검색 결과 → 주변 후보.
- 메시지: 서로 만날 구체적인 픽업 장소부터 정리.
- 지도: 위치·차단 영역 확인. 현장 정차 가능 여부 확인 필요.
- 초대: 운전자가 만든 링크에 동행 참여.
- 준비: 동행이 준비 완료 → 운전자 화면 반영.

## 장면 2 — 변경을 서로 확인하기

- 상황: 동행이 현대자동차 양재사옥 쪽에서 만나기를 제안.
- 선택: 위치 공유는 거부하고 계속 진행.
- 조작: 탑승자 장소 변경 제안 → 운전자 수락.
- 메시지: 상대 수락 전에는 확정 장소가 바뀌지 않음.
- 주의: 고정 목록 장소 변경은 이름 기반 합의이며, 이 장면을 native 좌표 안내 성공으로 연결하지 않음.

## 장면 3 — 도착부터 탑승 완료까지

- 조작: 운전자 도착했어요 → 탑승자 탑승했어요 → 운전자 종료 확인.
- 메시지: 위치 추정이 아닌 양측의 명시적 확인.
- 결과: 한 번의 픽업 완료.

## 장면 4 — 세 명을 두 지점에서 태우기

- 상황: 동행 A는 첫 지점, B·C는 같은 두 번째 지점에서 승차.
- 조작: 출발 설정 → 사람별 초대 → B·C 공동 지점 지정 → 각자 참여·준비.
- 운전자: 다음 지점 선택 → 도착 표시.
- 탑승자: 사람별 탑승 확인.
- 메시지: 같은 지점에 남은 사람이 있으면 다음 지점 진행을 제한.

# 함께 픽업 · 로컬 웹 0.1.0

기존 서버 `node experiments/pickup-board/server.mjs` 실행 후 `http://127.0.0.1:4180/multi`로 접속한다. 메인 화면의 **여러 명 함께 픽업** 링크도 같은 화면을 연다. 이번 작업의 별도 시연 서버는 4196 포트다.

1. 출발 지점과 선택적 최종 목적지를 고른다. 현재 UI의 선택지는 기존 양재 OSM 데이터의 후보 3곳이다. 실제 차량 위치 자동 수집·전국 검색이 아니다.
2. 순서 추천을 시험하려면 **합성 이동시간으로 순서 추천 시연**을 직접 선택한다. 기본값은 수동 계획이다.
3. 사람별 이름·승차 지점을 추가한다. 기존 지점의 **같은 지점 함께 승차**를 명시 선택하면 여러 명을 한 경유지에서 태운다. 별도 지점은 가까워도 자동 병합하지 않는다.
4. 독립 초대 링크를 각 사람에게 전달한다. 로컬 시연에서는 **탑승자 화면 열기**로 새 탭에서 참여한다. 링크 복사와 발송은 별개이며 앱이 메시지를 보내지 않는다.
5. 탑승자는 본인 지점에 동의하여 참여하고 준비 상태를 표시한다. 운전자는 수동 순서를 바꾸거나 추천을 조회·적용한다.
6. 운전자의 **다음 픽업 선택 → 이 지점 도착 확인**, 탑승자 본인의 **탑승했어요**로 진행한다. 같은 지점의 모든 사람이 탑승 또는 명시 취소되어야 다음 지점으로 넘어간다.
7. 남은 사람이 없으면 회차를 종료한다. 모두 탑승/일부 탑승·취소/모두 취소를 구분한다.

## 제공하는 것과 남은 연결

- 회차당 총 6명, 메모리 100회차/24시간 한도. 6명은 초기 소프트웨어 범위이며 차량 정원·SDK 한도 주장이 아니다. 실제 차량 정원은 사용자가 준수한다.
- 사람별 초대·세션·준비·탑승·취소와 본인 정보만 반환하는 권한 분리. 정확한 위치 수집은 하지 않는다.
- 지점별 경유 계획과 추천의 조회/명시 적용 분리. 활성 지점 고정, 미준비 자동 제외 없음, 입력 변경/60초 만료 시 추천 무효화.
- 이동시간은 방향별 행렬로 계산하고, 최종 목적지까지 포함해 최대 6! 순열을 비교한다. 동점은 기존 순서를 유지한다. 구간값은 0~604800 정수 초 계약이다.
- `MultiBoard({provider})`로 실제 경로 공급자를 주입할 수 있다. 현재 기본 서버에는 연결된 공급자가 없다. `provider(input, signal)`는 `mode:'real', source, observedAt, expiresAt, matrix`를 반환해야 한다. 행렬 키는 `origin`, stop ID, 선택적 `destination`; 모든 다른 노드 쌍의 방향별 비용이 필요하다. API 키를 클라이언트 입력으로 받지 않는다.
- 합성 모드는 실제 좌표/도로와 무관한 방향별 비용을 사용한다. 실패한 실제 계산을 합성 성공으로 대체하지 않는다. 시간표·준비 완료 예상 시각·대기시간 최적화는 미구현이다.
- **현대 내비 경유 전송과 실제 안내는 미연결**이다. `navigation:'unconnected'`이며 **다음 픽업 선택**은 앱 내부 상태만 바꾼다. 최종 목적지까지의 실제 주행·도착을 증명하지 않는다. Android 소스/에뮬레이터는 이 작업에서 수정하지 않았다.
- 초대 이후 승차 지점 수정·공동 장소 재합의는 미구현이다. 현재는 해당 사람을 취소하고 새로 추가한다. 취소된 사람도 회차의 총 6명 한도에 포함된다.
- 공개 HTTPS/물리폰·실차/CarUxRestrictions 미연결. 웹에서 주차 확인 버튼으로 이를 대체하지 않는다. 주행용 배포본이 아니다.

## API

`POST /api/trips` 생성, `GET /api/trips/:id` 인증별 조회, `POST .../preview` 초대 지점 확인, `POST .../join` 일회 참여, `POST .../actions` 상태 변경, `POST .../recommend` 추천 조회. 상태 변경/추천 요청은 Bearer 및 최신 `version`, 조회에서 발급한 15초 `view`, 일회 `requestId`가 필요하다. 응답의 `invites`는 운전자 전용이다.

초대는 URL fragment에 담고 서버 요청은 JSON 본문으로 전달한다. 참여 전 복구 키를 저장하며 같은 키의 재시도는 5분 동안만 가능하다. 참여 응답 후 저장 실패 시 현재 화면의 메모리 세션은 유지하고 복원 제한을 안내한다. 브라우저 저장 자체가 불가능하면 초대를 소비하기 전에 참여를 중단한다.
