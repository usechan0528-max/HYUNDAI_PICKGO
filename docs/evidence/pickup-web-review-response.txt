## Verdict

No P0 found in the loopback default path. Do not start the HTTP or browser checks until the P1 items are fixed, since the first browser run would exercise the storage and join path directly. The review is from reading the supplied sources only. I used no tools and made no edits.

## P1: fix before the HTTP and browser checks

**1. The join consumes the invite before the session is proven storable** (`app.mjs`, `$('join').onclick`)
- The POST to `/join` runs first, then `save(joined)`. If `sessionStorage` throws, the rider token lives only in memory, the invite is already spent, and the hash has been removed. A reload then leaves the rider with no way back in.
- Minimum fix: probe storage before calling join, and do not join if the probe fails.

```js
const canPersist = () => { try { sessionStorage.setItem('pickupProbe', '1'); sessionStorage.removeItem('pickupProbe'); return true; } catch { return false; } };
// in join.onclick, after validInvite check:
if (!canPersist()) { $('notice').textContent = '브라우저 저장이 제한되어 참여하지 않았습니다. 초대 링크를 그대로 보관해 주세요.'; return; }
```

**2. Warnings are wiped within 2 seconds** (`app.mjs`, `refresh()`)
- Every successful poll runs `$('error').textContent = actionError`. That erases the storage-denied warnings, including the one that says a reload loses the join. The driver create path is affected the same way.
- Minimum fix: add a separate `<p id="notice" role="alert">` that `refresh()` never writes. Route all storage and join warnings there.

**3. The verification path for the optional phone API is unconfirmed** (`server.mjs`)
- The `PhoneBoard` import was replaced with `RecommendationBoard`. The `/api/rooms/:id/phone` route only runs when `board.phone` exists. Otherwise it returns 405 silently, and `sweep` is optional-chained, so it also disappears quietly.
- Confirm that `recommendation/board.mjs` extends `PhoneBoard`, and add a server test that `GET` and `POST /phone` return 200 through `createServer()`.

**4. Public mode is open to a one-client DoS** (`domain.mjs`, `create`; `server.mjs`)
- `POST /api/rooms` requires no auth, and the cap is global at 100 rooms for 24 hours. A single anonymous client can fill every slot and block room creation for everyone.
- This is not a current bug, since nothing is deployed. It must be gated before `PICKUP_PUBLIC_ORIGIN` is used for real traffic. Minimum: a per-IP rate limit on `POST /api/rooms` and `/join` at the proxy.

## P2

**5. Driver joins their own room and loses the driver token** (`app.mjs`)
- If the stored session is the driver of room X and the pasted invite is for room X, the join goes through. The tab's driver credential is replaced by a rider credential, and that cannot be recovered.
- Fix: check for `previousSession.id === incoming.id && role === 'driver'` and refuse with a message.

**6. Switching sessions silently drops driver access** (`app.mjs`, `joinHint`)
- The hint says the old session is not cancelled. That is true on the server, but this tab loses the only driver credential for the old room.
- Fix: say so in the copy for driver sessions, or keep the old session in a `pickupSessionPrevious` key.

**7. The invite card flickers and clears on staleness** (`app.mjs`, `render()`)
- `canInvite` includes `valid`. A tab switch sets `online = false`, which hides the invite box, clears the link, and wipes the "copied" status. A driver who switches apps to paste the link loses it.
- Fix: derive `canInvite` from session and state only. Gate only `copyInvite.disabled` on `valid`.

**8. Lost join response leaves a dead end**
- The server consumes the invite, the response is lost, and every reload returns 403. This is your known limit. A cheap mitigation is to show a specific message on 403 after an earlier attempt, and to clear the pending invite. The stronger fix is a client nonce persisted before the join call, with the server returning the same token for 5 minutes.

**9. Test gaps in `web-invite.test.mjs`**
- Storage-denied join must not call `/join`.
- A poll must not erase the notice.
- Driver-own-room join must be blocked.
- 403 vs 404 messages must differ.
- Ended and stale states must hide the join controls.
- The `error` assertions will need to move to `notice` after fixes 1 and 2.
- Add HTTP tests in `web-origin.test.mjs` for a proxied Host of `pickup.example` against the real `createServer`.

**10. Deployment note for the proxy**
- nginx defaults to `proxy_set_header Host $proxy_host`, which will fail the Host check with 403. It must be `$host`. Caddy preserves Host by default.
- Set HSTS at the proxy, since the app does not send it.

## P3

- `join.onclick` sets `disabled = true` and then returns early on invalid input without a `finally`. It is effectively dead, but the button would stay disabled if it were reached.
- 403 is mapped to "already used" for expired or ended rooms. Map 404 and ended states separately.
- The copy click is silent when stale. Show "확인 중" instead.
- `inviteHelp` says "링크를 가진 한 사람만 참여". More accurate wording is "먼저 여는 한 사람만 참여할 수 있습니다".
- Mobile prep: `AbortSignal.timeout` needs Safari 16+, and `crypto.randomUUID` and `navigator.geolocation` need a secure context. Plain-HTTP LAN testing will break `act()`.

## Checked and looks right

- The fragment is read and then removed with `replaceState`. The invite goes in the POST body, not the URL. `noopener noreferrer` on the preview link.
- `join` makes no geolocation call, and the invite copy matches that.
- `requestOrigin` fails closed. `X-Forwarded-*` is ignored, `Origin: null` is rejected, and the loopback default keeps `127.0.0.1` only.
- `parsePublicOrigin` fails at startup on a bad value.
- The textContent use and the CSP mean no XSS path is visible.
- Stale and ended handling holds: `unavailable` covers 401, 403, and 404, and `new` appears for ended rooms.
