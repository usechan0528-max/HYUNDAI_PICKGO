**판정:** 결론의 방향은 대체로 타당하다. 공개 문서 존재와 이용 가능성을 구분하려는 점도 맞다. P0 차단 사항은 없다. 다만 검증 상태 표기와 "사용 가능" 근거에 P1 수준의 과장이 있고, 3.0.5 호환성과 좌표 순서 검증이 빠져 있다.

**P0:** 없음. 입력에 실행 증거가 없으므로 "런타임 가능" 주장은 어디에도 없다. 이 점은 문서가 이미 명시하고 있다.

**P1**

1. **검증 상태 과장.** 문서는 여러 링크를 "직접 확인했다"고 쓰고, 일부는 "Chrome 렌더링 본문에서 확인"이라고 쓴다. 그런데 같은 문서에서 Hyundai FAQ는 "검색 추출문만 확보, 직접 open은 timeout/502"라고 적고, routo 메인은 리디렉션만 확인했다고 한다. 본 검수는 링크를 열지 않았으므로 어떤 링크도 검증했다고 말할 수 없다. 표에 "작성자 열람 확인 / 검색 추출만 / 미열람"을 링크별로 나눠 적어야 한다.

2. **"신청 없이 사용 가능"을 이용허가 근거로 사용.** 근거는 SDK 사용 신청 페이지의 문장 하나다. 문서는 회원가입·배포 심사를 별개로 적지만, 결론부에는 이 문장이 "사용 가능"의 근거로 흘러들어간다. 또한 의존성 저장소가 `nexus-playground`이다. 공모전 APK 배포·Pleos 탑재 조건은 확인되지 않았다. 그대로 "공개 Maven"이라고 쓰면 가용성과 허가가 섞인다. 원문 문구와 날짜를 인용하고, 배포 조건은 미확인으로 남겨야 한다.

3. **런타임 경로의 버전 불일치 미검토.** 전용 에뮬레이터는 2.1.0인데 의존성은 NaviHelper 3.0.5다. 2.1.0 에뮬레이터에서 3.0.5 API가 동작하는지 문서에 근거가 없다. 실행 담당 채팅이 이 조합으로 빌드하면 "API 부족"이 아니라 환경 문제로 실패할 수 있다.

4. **좌표 순서 위험.** 3.0.5에서 생성자 순서가 위도·경도로 바뀌었다. routo는 검색 `location`(위도·경도)과 경로 예시(x=경도, y=위도)가 다르다. 순서가 틀리면 오류 없이 엉뚱한 위치가 표시된다. 문서는 "혼용하지 않는다"고만 쓰고 이를 잡을 테스트가 없다.

5. **놓친 대안.**
   - 가장 작은 우회로: 사용자가 기본 내비 검색에서 목적지를 직접 고르고, PICKGO가 `getDestinationInfo`로 읽는다. 검색 결과 반환 계약 없이 가능하며, 문서가 이미 쓰는 리스너 API로 구현할 수 있다. 문서에는 이 흐름이 대안으로 적혀 있지 않다.
   - 저장소에 `PICKGO_KAKAO_FALLBACK_2026-11-04.md`가 있는데 이 조사 문서가 참조하지 않는다. 국내 장소검색 시연 폴백으로 Kakao Local, Tmap 등을 비교 대상으로 적어야 한다. 공개 API 범위를 벗어난다는 이유로 빼더라도, 그 판단은 명시해야 한다.

**P2**

- Hyundai Developers FAQ의 "개발 프로젝트/인증, 테스트 차량·샘플 안내" 내용은 검색 추출문에만 근거한다. 미열람으로 표시해야 한다.
- 표의 "정확한 공개 연결점"은 과장이다. 근거인 `sdk-declarations.txt`, `compile.txt`는 이 입력에 없다. "정적 선언/컴파일 기록 참조"로 낮춰 쓰는 편이 맞다.
- POI 선택 전후 비교에는 기준 상태(baseline)가 없다. 기존 목적지가 남아 있으면 선택 결과로 오판한다. 시작 전 목적지 상태를 기록하는 전제가 필요하다.
- `requestTrip`의 "경로 무변경"은 미확인이다. 시연 후보에 올리기 전 확인이 필요하다.

**P3**

- 연락 초안은 미발송 상태가 명확하다. 다만 제품 정보가 많이 들어 있으므로, 발송 전에는 승인 범위를 다시 확인하는 편이 안전하다.

**다음 최소 검증 순서** (실행은 승인 후)

1. 로컬 단위 테스트: 서울시청 좌표 `(37.5665, 126.9780)`을 NaviHelper 생성자와 routo 요청 변환에 통과시켜 필드 순서를 확인한다. 네트워크가 필요 없다.
2. 3.0.5 빌드를 2.1.0 에뮬레이터에서 실행하고 로그를 남긴다. 실패하면 에뮬레이터 버전 문제인지 API 문제인지 분리한다.
3. 실행 전 목적지 상태를 기록한 뒤, 기본 내비에서 수동으로 목적지를 고르고 `getDestinationInfo`를 1회 읽는다.
4. "신청 없이 사용 가능" 문구의 원문과 날짜를 캡처하고, 배포 조건은 Pleos에 문의하기 전까지 미확인으로 둔다. 문의는 승인 대상이다.
5. FAQ와 routo 링크를 열어 확인 상태를 링크별로 기록한다.

**검수 범위:** 입력 텍스트만 검토했다. 링크, 네트워크, 파일, 도구는 사용하지 않았고 파일도 수정하지 않았다. 다만 plan 모드가 켜져 있어 계획 파일도 쓰지 않았다. 구현이나 실행을 시작하려면 모드를 해제하거나 계획 승인을 받아야 한다.
