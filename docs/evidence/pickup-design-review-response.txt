# 픽업 약속판 구현 검수 (claude-haiku-5-5, 읽기 전용)

도구는 쓰지 않았고 정적 읽기만 했습니다. 아래는 모두 **코드 기반 추론**이며, 렌더링이나 실행으로 확인한 것이 아닙니다. 제공된 테스트 16건 통과 결과는 사용자가 보고한 내용을 그대로 인용한 것입니다.

## 결론
- **P0 없음.** 서버 검증은 요구한 권한과 상태 규칙을 막고 있습니다. 탑승자만 준비 상태를 바꾸고, 자기 제안을 수락하지 못하며, 철회는 제안자만 하고, 종료 후 변경과 일회성 초대를 차단합니다. 조회 토큰 TTL(서버 8초, 클라이언트 6초)에도 여유가 있습니다. 다만 클라이언트 잠금은 UI 보조일 뿐이고, 실제 방어선은 서버입니다.
- **P1 3건**은 실제 시연 전에 고치거나 실측해야 합니다.

## P1

**1. 상태가 없을 때 "새 약속 시작"이 보입니다 [코드추론]**
`render()`에서 `state`가 없으면 `active`가 `false`가 되고, `$('new').hidden = !!active && !unavailable`는 `false`를 반환합니다. 첫 로드나 서버 미응답 상태에서 세션만 있으면 버튼이 보입니다. 클릭하면 `sessionStorage`의 driver token과 invite가 지워져 해당 회차로 돌아갈 방법이 사라집니다. 테스트는 상태를 받은 뒤의 403 경로만 다룹니다.
- 권장: 세션은 있고 `state`가 없으면 버튼을 숨기거나, 삭제 전에 확인 절차를 둡니다.

**2. 480×720에서 stale 설명이 숨겨집니다 [코드추론]**
`@media(max-width:899px) and (max-height:780px)`가 `.proposal p`와 `.event`를 `display:none`으로 만듭니다. 그러면 다음 요소가 사라집니다.
- `#proposalText`: "마지막 확인 당시 제안입니다. 현재 상태는 미확인입니다."와 "기존 승차지점은 그대로입니다"
- `#lastEvent`: "마지막 확인 기록 · 현재 미확인:" 접두어

남는 것은 라벨 `이전 제안 · 현재 미확인`과 상단 `연결 확인 필요`뿐입니다. 요구사항상 stale 문구는 유지되어야 하므로 숨기지 말고 짧은 문구로 줄이는 쪽을 권장합니다.

**3. 레이아웃 초과 위험 [추정 · 실측 필요]**
- **1280×720:** 제안 패널 안에 라벨, 제목, 설명, 버튼 2개(각 88px)와 간격이 들어갑니다. 대략 430px 안팎으로 보이는데, 셀 높이는 약 360px로 추정됩니다. 버튼이 패널 밖으로 넘쳐 `#lastEvent`나 하단 버튼과 겹칠 수 있습니다.
- **480×720:** 세로 합계가 약 630px로 추정되는데, `main`의 가용 높이는 약 588px입니다. `main`에 `overflow` 지정이 없어서 하단 버튼이 footer 영역과 겹칠 수 있습니다.

직접 확인해야 할 항목입니다. 두 화면에서 요소 `getBoundingClientRect()`의 bottom과 `scrollHeight`를 측정하면 됩니다.

## P2

- **본문 18px 기준 미달 [코드 확인]:** 479px 이하에서 `.demo`, `.topline`, `footer`, `.welcome-copy .section-label`이 16px입니다. footer에는 유일한 주행 금지 문구가 있으므로 18px 이상을 권장합니다.
- **차량 상태 미연동 문구 없음:** footer는 "Gleo·차량 미연결 · 주행 중 사용 금지"만 말합니다. "실제 차량 운행 상태와 연동되지 않은 로컬 시연"을 명시하면 오인을 줄일 수 있습니다.
- **"운전자 화면" 라벨:** 차량 운전자를 떠올리게 할 수 있습니다. "약속 관리 화면" 같은 이름을 검토해 볼 만합니다. 이름은 사용자가 정할 부분입니다.
- **색으로만 stale 표시:** `.facts.stale .place`는 색만 바꿉니다. 텍스트 라벨이 있어서 영향은 작습니다.
- **스크린리더 반복 낭독 가능성 [코드추론]:** `render()`가 500ms마다 `#lastEvent`의 `textContent`를 다시 씁니다. 값이 바뀔 때만 갱신하는 편이 안전합니다.
- **오버레이 포커스 관리:** `#editPlace`와 `#endConfirm`은 `role="dialog"`가 없고, 열 때 포커스를 옮기지 않으며, 닫을 때 복귀하지 않습니다.
- **충돌과 연결 실패가 같은 취급을 받습니다:** `act()`의 catch는 409 충돌에도 `online=false`를 설정합니다. `finally`의 refresh로 바로 복구되지만 잠깐 "연결 확인 필요"가 뜹니다.
- **영문 오류 노출 가능성:** `api()`의 `response.json()`이 try 밖에 있어서 HTML 응답이 오면 영문 SyntaxError가 `#error`에 그대로 나옵니다.
- **종료 권한 확인:** 서버는 탑승자와 운전자 모두 종료할 수 있게 합니다. 의도한 설계인지 확인이 필요합니다.
- **사소한 항목:** 같은 준비 상태를 다시 누르면 version이 올라가는 요청이 나갑니다. `visibilitychange`마다 상태가 잠깐 stale로 깜빡입니다.

## 테스트 공백
- 상태가 없는 첫 로드나 서버 다운에서 `#new`가 숨겨지는지 검증하지 않습니다.
- 480×720 CSS 숨김은 fake DOM에서 검증되지 않습니다. fake DOM은 CSS를 적용하지 않습니다.
- 종료 상태에서 `#new` 표시와 수락/거절 숨김을 검증하지 않습니다.
- 409 충돌 시 UI 표시를 검증하지 않습니다.

## 실측 체크리스트
1. 1280×720과 480×720에서 제안 상태의 요소 bottom 값을 측정합니다.
2. 480×720에서 stale 상태를 만들어 `#proposalText`와 `#lastEvent`가 보이는지 봅니다.
3. 첫 로드 전에 서버를 끊고 `#new`가 보이는지 확인합니다.
4. 요구의 "Pleos 가로·세로" 기준은 제공된 코드에 근거가 없어서 검증할 수 없습니다. 참고 항목으로만 둡니다.
