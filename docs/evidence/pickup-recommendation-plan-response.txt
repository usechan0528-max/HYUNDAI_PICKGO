# 픽업 지점 추천 설계 비평 (읽기 전용)

## 총평
보안 경계(서버 소유 provider, HTTP 입력 불신), 동의 epoch, TTL, 재검증 흐름은 방향이 맞습니다. 다만 최소 구현 단계에서 아래 위험이 남아 있습니다.

## 핵심 위험

**1. 상속 결합 (`RecommendationBoard extends PhoneBoard`)**
- PhoneBoard의 일회성 동의 경로가 상속을 통해 연속 위치 경로로 새어 들어갈 수 있습니다. 설계는 "조용히 확장 금지"를 명시하지만, 상속 구조에서는 override를 빠뜨리기 쉽습니다.
- 권장: 상속 대신 합성(composition)을 쓰고, 동의 타입을 `oneShot`/`continuous`로 분리한 별도 저장소에 둡니다. 연속 동의 검사기는 일회성 동의를 받으면 반드시 거부해야 합니다.
- 공유 파일은 핸드오프 전까지 수정할 수 없으므로, Board hook 지점이 실제로 존재하는지 먼저 확인해야 합니다. 없다면 hook 추가 자체가 핸드오프 의존 항목입니다.

**2. 시간 기준 혼용**
- 관측 나이(`fix.timestamp`, 클라이언트 벽시계)와 서버 단조 시계를 섞으면 시계 왜곡으로 TTL 15초가 무력화됩니다.
- 권장: 서버 수신 시각(단조) 기준으로 판정하고, 클라이언트 timestamp는 "더 오래됐다는 증거"로만 씁니다(`max` 적용). 미래 timestamp는 거부합니다.

**3. 경쟁 조건**
- 선택 → 제안 → 상대 수락 사이에 동의 철회, 위치 만료, `placeRevision` 변경이 끼어들 수 있습니다.
- 수락 시점의 재검증은 Board의 version CAS와 같은 원자 단위여야 합니다. 비동기 provider 호출 뒤에 version을 다시 비교하지 않으면 TOCTOU가 발생합니다.
- tombstone은 영구 보관하지 말고 epoch 상한 + TTL로 정리해야 메모리가 누수되지 않습니다.

**4. 임의 장소 등록**
- 방 단위 서버 등록은 좋습니다. 다만 등록 ID는 추측할 수 없게 하고, 방 종료와 동의 철회 시 함께 삭제해야 합니다. 그렇지 않으면 위치에서 파생된 데이터가 남습니다.
- 클라이언트는 `candidateId`만 보내고, 좌표나 이름은 절대 받지 않아야 합니다.

**5. 증거 커버리지 판정**
- "도착 예상 + 체류"를 덮는 유효 창을 판정하려면 ETA 불확실성 마진이 필요합니다. 마진이 없으면 경계 사례에서 오판합니다.
- 증거 필드 중 하나라도 누락되면 기본값은 제외여야 합니다. `unknown`을 허용으로 취급하는 코드 경로를 테스트로 막아야 합니다.

**6. 점수와 설명**
- 실험적 가중치는 서버 상수로 고정하고, 버전 태그를 스냅샷에 포함해야 합니다.
- 설명 문구에 "최적", "합법 확인됨"과 같은 표현을 쓰지 말아야 합니다. 데모 provider에서는 "합성 데이터" 라벨을 강제합니다.

**7. 프라이버시 노출**
- 상대방에게 상대의 실시간 좌표나, 도보 시간으로 역산 가능한 정밀 값이 노출되지 않는지 확인해야 합니다. 후보 응답은 반올림/구간화가 필요합니다.
- 로그에 좌표가 남지 않아야 합니다.

**8. 브라우저 생명주기**
- `visibilitychange`, `pagehide`, BFCache 복원 시 자동 재개를 금지해야 합니다.
- 서버 철회 요청이 실패하더라도 서버 TTL로 자연 만료되므로 안전합니다. 이 실패 경로를 테스트에 포함해야 합니다.

## 필수 게이트
1. 기본 provider는 미구성 상태이며, 모든 추천 요청에 명시적 `unavailable`을 반환합니다(빈 후보와 구분).
2. 데모 provider는 별도 플래그로만 활성화되고, 응답에 `synthetic: true`를 포함합니다.
3. 프로덕션 활성화 조건: 실 라우팅 계정 + 커브 허가 데이터셋 + 드라이버 SDK 실측 검증. 셋 다 현재 미충족입니다.
4. 공유 파일 연결은 핸드오프 이후 별도 리뷰를 거칩니다.
5. 테스트 범위: HTTP 주입 거부, 동의 경계, 만료·철회·지연 콜백, provider 실패·타임아웃, 후보 0개, 동시 수락 경쟁, 합의 장소 불변.

## 상태 구분

| 구분 | 상태 |
|---|---|
| 데모 (합성 PLACES + 합성 provider) | 구현·검증 가능 범위. 완료로 보고 가능 |
| 실 위치 연속 수집 | 브라우저 경로만 가능, 드라이버 SDK 미검증. 차단 |
| 실 라우팅 | provider/계정 없음. 차단, 성공 주장 금지 |
| 커브 정차 허가 증거 | 데이터셋 없음. 차단, 모든 실후보 제외가 정상 동작 |

J-01은 범위에서 제외했습니다.
