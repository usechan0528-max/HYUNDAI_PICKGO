**Scope:** Read-only review of the pasted snapshot. I ran no tools. `server.mjs`, `phone-domain.mjs`, and `domain.mjs` were not provided, so the base `act`, `sweep`, room prune, and `/actions` routing are unverified.

## P0

**1. The evidence gate is keyed to a proposal binding, not to proposal origin.**
- Evidence: `board.mjs` `act()` blocks `accept` only when `e.proposal.proposalId === r.proposal?.id`.
- A proposal created through ordinary `/actions` `propose` never sets `e.proposal`, so its later `accept` passes the override untouched.
- A replacement proposal is also unguarded. The stale binding from the earlier proposal no longer matches, and nothing clears it on `propose`.
- The test "ordinary actions cannot bypass" covers only a binding created by `select`.
- Impact: in a room that is supposed to require fresh recommendation evidence, the agreed place can change with no route or permission recheck.
- Severity: P0 if `/actions` routes through `RecommendationBoard.act` (unverified). Otherwise P1.
- Fix: mark each proposal with an origin in `select`. In `act()`, reject `accept` for any proposal not explicitly marked manual while recommendation mode is active, and clear the binding on any `propose`.
- Tests to add: propose then accept via `/actions`; a manual propose that replaces a recommended proposal, then accept.

## P1

**2. The retention claim is not implemented as written.**
- `page.html` says the last location is deleted at the "다음 정리 주기" (next cleanup cycle).
- `sweep()` runs only inside `recommend()`, `act()`, and `status()`. No timer appears in the snippets.
- In an idle room, raw lat/lon stays in `e.driver.fix` and `e.rider.fix` indefinitely. The 15s expiry is logical, not physical.
- Fix: schedule a sweep, or change the copy to match the behavior.
- Test: leave a fix in an idle room, advance the clock with no requests, and assert the memory is cleared.

**3. Freshness trusts client-supplied `ageMs`.**
- `publish` computes `freshFix` from receipt time plus the client's `ageMs`. A client that sends `ageMs: 0` for an old sample passes.
- This is dormant today because live sources are blocked and only synthetic is allowed.
- Fix before browser geolocation goes live: take the sample timestamp from the provider, not the client.

**4. The provider timeout does not cancel work.**
- `Promise.race` at 3000 ms clears `busy` in `finally`, but the underlying `evaluate` keeps running.
- Repeated clicks against a hung live provider would stack unbounded calls.
- Fix: pass an `AbortSignal` to the provider, or hold `busy` until the promise settles.
- The existing timeout test covers only that `busy` resets, using a never-resolving evaluate.

## P2

**5.** The consent cap is a permanent self-lockout. Each role gets 100 consent IDs for the room's lifetime, and after that every grant fails. The UI message "새 동의가 필요합니다" does not explain this. Revokes past the cap are silently unrecorded.

**6.** Privacy minimization needs a product decision. `status()` gives each party the counterpart's freshness boolean. The driver also receives proposal evidence (walk seconds and meters) derived from the rider's location. The copy does not state this.

**7.** Summary and test gaps:
- The summary says page tests cover revoke. `recommendation-page.test.mjs` has no server-revoke case; it only tests the local `notify` path.
- No test covers the consent cap, the `/actions` propose bypass (item 1), idle-room retention (item 2), or spoofed `ageMs` (item 3).

**8.** `entry()` allocates on any GET to the recommendation endpoint. It is pruned only when the room is removed. This is minor.
