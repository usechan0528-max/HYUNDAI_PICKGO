C02 approved manual arrival/boarding feature design review. Read-only, no tools or source edits. Follow project principle: no inferred arrival/boarding from location or ready; no SDK/ETA/persistence. Codex implements, actual Opus 5.5 reviews important design. Propose minimal corrections, not a rewrite.
Current Board: active/ended, ready boolean, joined, agreed place, optional proposal; authenticated driver/rider capabilities; each mutation checks active, version, server read lease 8sec, unique requestId, proposalId. Client locks stale after6sec and polls2sec. Either role can explicitly end (even before join), never automatic completion.
Proposed: pickup stage waiting/arrived/boarded separate from active/ended; outcome null/completed/cancelled. Driver arrive only with rider joined, waiting, no pending proposal. Rider board only arrived with no pending proposal. Driver undo-arrival only arrived; rider undo-boarding only boarded, returns arrived. All manual, all version/lease protected. Ready and place proposal forbidden while boarded. Place proposal allowed arrived but boarding blocked until proposal resolved. Accept different place resets stage waiting; reject/withdraw preserves arrival. End either role always available, completed iff boarded else cancelled. UI explicit labels and end confirmation says completion vs cancellation; confirmation should bind the viewed version/stage so concurrent changes invalidate the confirmation, requiring reread/reconfirmation. Undo uses explicit named secondary button and immediate server event, no auto retries. End terminal, undo then permitted only before end. Arrival is self-report for agreed place, not proof of location. Ready independent, never prerequisites for arrival/boarding except joined.
