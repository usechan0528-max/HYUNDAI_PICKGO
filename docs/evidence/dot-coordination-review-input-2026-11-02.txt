### 프로젝트 기억과 작업 상태

사용자 승인으로 ai-memory를 이 프로젝트의 장기 기억·작업 상태·인수인계 도구로 사용한다. 범위는 `workspace="default"`, `project="hyundai_ai"`로 지정한다. 수집은 allowlist로 제한하고 이 프로젝트의 마커로 허용한다. 다른 저장소에 마커를 추가하는 것은 별도 범위 결정이다. 프로젝트 간 프로필 공유는 사용하지 않는다. `docs/`의 결정·API·검증 증거는 실제 파일·명령 결과와 연결하며, 기억이 현재 지침이나 실행 증거를 대신하지 않는다.

### 상시 협업과 역할별 모델

2026년 11월 2일 사용자 결정으로 Codex–Claude 협업을 **이 프로젝트의 모든 후속 작업과 새 세션에 적용하는 기본 방식**으로 정한다. 아이디어가 바뀌거나 대화가 새로 시작되어도 유지한다. 사용자가 변경하기 전까지 매번 협업 여부나 같은 범위의 전달 승인을 다시 묻지 않는다.

- Codex는 메인 기획·조사·구현·검증·통합을 책임진다. 기획의 후보 비교·중요 설계 판단에서는 Claude와 의견을 주고받고, 개발의 의미 있는 변경 묶음에서는 Claude 독립 검수를 수행한다.
- 아이디어 회의의 Claude는 **Opus 5.5** (`--model claude-opus-5-5`), 개발 과정의 검수는 **Haiku 5.5** (`--model claude-haiku-5-5`)를 사용한다. 후속 호출에도 모델을 명시하며, 기본 별칭이나 자동 fallback으로 지정 버전을 대체하지 않는다.
- 승인된 프로젝트 작업에 필요한 최소 기획 자료·고정 diff·관련 코드·테스트 증거를 Claude Code에 전달하고 답변을 읽어 후속 질문·수정·재검증하는 과정은 상시 협업 범위에 포함된다. 비밀키·자격 증명·불필요한 개인정보는 전달하지 않는다.
- Claude 호출 전 목표·입력 범위·수용 조건을 정하고, 호출 후 실제 모델·세션·오류 여부·주요 지적과 처리 결과를 기록한다. 의견이 다르면 근거와 실행 결과로 확인한다.
- 작은 문구 수정·상태 확인마다 호출하거나 같은 구현을 두 번 시키지는 않는다. 상시 협업은 이정표 중심으로 운영하며, 두 도구의 무한 반복이나 대화가 없는 동안의 자동 실행을 의미하지 않는다.
- 인증·네트워크·권한·사용량·모델 가용성 문제로 협업이 막히면 원인과 미검수 범위를 보고한다. 가능한 독립 작업은 이어가되 협업·검수가 완료되었다고 표시하지 않는다. 도구의 승인 심사와 권한 제한을 우회하지 않는다.
- 이 승인은 Claude와의 프로젝트 협업에 적용한다. 공개·외부 제출·push·계정·권한·서명키 변경 등 기존 별도 승인 경계는 유지한다.

- 후보별 점수·반론·폐기/보완 이유와 실제 Claude 호출을 기록한다. 새 앱 본개발·외부 모집·계정·권한·공개 승인은 별도 기존 경계를 따른다.

### Codex·Claude·Dot 상시 협업 (D-016, 2026-11-02)

- 사용자 승인으로 Codex는 개발 총괄, Claude Code는 독립 검수, Dot은 공식 자료 조사와 심사 기준 분석을 담당한다. 이 분담은 새 세션에도 유지하며 기존 Claude 모델 지정과 기획 반론 절차는 유지한다. Codex가 개발 우선순위·검증·최종 통합을 책임지고 Dot 조사 결과도 직접 검증한다.
- 승인된 프로젝트 범위에서 Codex가 필요한 최소 자료를 전달하고 작업을 하달하며, 보고 수신·보완 질문·후속 과제 배정을 반복한다. 같은 범위의 전달 승인을 재질문하지 않는다. 새 기능 범위, 공개·외부 제출·push·계정·권한·결제·비밀값 전달 승인은 포함하지 않는다.
- 현재 확인된 Dot 경로는 사용자의 로그인된 Chrome에서 ChatGPT Dot 대화에 메시지를 보내고 답변을 읽는 방식이다. 연결 테스트 회신을 실제 확인했다. 전용 API, 내부 서브에이전트 호출, 자동 문맥·토큰 공유 또는 Dot의 로컬 파일 접근을 확인한 것은 아니다. 대화 식별과 작업 상태는 `docs/DOTS_COLLABORATION_2026-11-02.md`에 기록한다. 과거 다른 환경의 접근 실패는 이력으로 구분한다.
- Dot은 공식 원출처 URL·제목·발행/갱신일·확인일과 근거 위치를 제시하고, 확인 사실·해석·미확인을 구분한다. 차량특화성·창의성·기술 활용성·사업성별로 J1 적용점, 반대 근거, 추가 검증을 연결한다. 비공개 배점·수요·SDK 실행 성공을 추정하지 않는다. 접근·자동 수집 제한을 준수한다.
- Dot과 Claude의 기본 파일 수정 권한은 없다. Dot은 조사 보고를 대화로 반환하고 Codex만 저장소에 통합한다. 작업 ID·입력 기준·수용 조건·전달/회신/검증/반영 상태를 따로 기록한다. 같은 과제를 중복 하달하지 않고 미해결 근거를 다음 과제로 삼는다.
- 활성 작업 중에는 이정표마다 보고를 회수한다. 대화 밖의 후속 확인은 실제 저장된 heartbeat에서만 수행하며, 저장 실패·접속 차단을 숨기지 않는다. heartbeat는 결과 도착·미해결 과제를 확인하고 필요한 한정 과제를 배정한다. 사용자에게는 의미 있는 변경·완료·실패·판단 필요 시 알리며, 변화 없는 상태를 반복 보고하지 않는다. 사용자가 중지하거나 프로젝트가 종료되면 중단한다.

### 역할별 책임

**사용자 결정:** 가용 사용량이 더 많은 Codex를 메인으로, 상대적으로 제한된 Claude Code를 서브 에이전트와 검수자로 사용한다. 실제 토큰 한도·남은 양·비용을 추측하지 않는다. 이 역할 분담은 논리적인 작업 방식이며, 두 제품 사이의 자동 호출·세션 공유·토큰 공유를 전제하지 않는다.

**Codex 메인:** 전체 맥락 정리, 공식 자료 조사, 기획과 아키텍처 제안, 구현, 넓은 범위의 빌드·테스트, 통합, 버전·문서 관리, 진행 보고와 인수인계를 맡는다. 승인된 범위의 기술 판단을 책임지되 앱 주제·새로운 기능 범위·공개·제출 등 사용자 결정 사항을 대신 승인하지 않는다. Claude에게는 독립적으로 판단 가능한 작은 작업이나 의미 있는 변경 묶음의 검수를 위임한다.

**Claude 서브와 검수자:** 기본 모드는 소스 수정 없는 독립 검수다. 전달된 요구사항·diff·필수 주변 코드·실행 증거와 알려진 문제를 바탕으로 결함과 위험을 찾는다. 전체 기능을 다시 구현하거나 아키텍처를 처음부터 재설계하지 않는다. 분리 가능한 조사·테스트 사례 보완·작은 수정은 맡은 목표와 파일 범위가 명시된 경우에만 수행한다. 판단에 필요한 문맥이 부족하면 필요한 파일·심볼·호출 경로를 구체적으로 요청한다.

### 적은 문맥으로 위임하는 방법

Codex는 위임 전에 목표, 검토 기준 커밋 또는 고정 스냅샷, 변경 diff, 필요한 파일, 수용 조건, 실제 테스트 결과, 알려진 문제를 묶는다. 전체 대화·모든 문서·저장소 전체를 그대로 전달하지 않는다. 안전·권한·API 의미를 판단할 주변 코드가 빠지지 않도록 하며, 불필요한 기록만 덜어 낸다. 전체 조사가 꼭 필요하면 Claude는 그 이유와 추가 범위를 먼저 알린다.

핵심 기능 한 흐름 완성, SDK 어댑터 연결, 주행 제한 변경, 제출 후보처럼 의미 있는 이정표에서 검수한다. 작은 편집마다 Claude를 호출하거나 같은 파일을 반복 재검토시키지 않는다. 재검수는 이전 지적의 수정 diff와 영향 범위를 중심으로 한다. 긴 기록은 Codex가 결론·결정·열린 문제·증거 위치로 압축하고, 검수에 필요한 반대 증거나 실패 기록을 누락하지 않는다.

소스 수정 없는 검수에서도 범위 안의 필요한 검증 명령은 실행할 수 있다. 테스트가 빌드 산출물·캐시를 만들 수 있으므로 명령의 영향과 실행 위치를 확인한다. 비용이 크거나 외부 상태를 바꾸는 명령, 전체 저장소의 광범위한 재검증은 자동으로 실행하지 않는다. 실행하지 못한 검증은 미실행 또는 차단으로 보고한다.

### 검수 결과와 통합

Claude는 중요한 지적부터 보고한다. 각 지적에 심각도, 파일·줄 또는 심볼, 관찰 근거, 사용자에게 미치는 영향, 최소 수정안을 적는다. 재현하지 않은 추론과 불확실성, 확인한 범위와 빠진 문맥을 구분한다. 무관한 스타일 수정이나 전체 재작성 제안으로 결과를 채우지 않는다.

- **P0:** 즉시 중단이 필요한 안전·비밀값 노출 등 중대한 위험.
- **P1:** 핵심 흐름 실패, 잘못된 권한·상태 처리 등 제출 전 해결이 필요한 문제.
- **P2:** 제한된 조건의 결함 또는 유지보수 위험.
- **P3:** 동작에 큰 영향이 없는 개선 제안.

문제가 보이지 않으면 확인한 범위에서 뚜렷한 문제를 찾지 못했다고 보고한다. 이것을 전체 앱의 안전성이나 모든 테스트 통과로 확대하지 않는다. 심각도와 근거가 충돌하면 사실을 다시 확인한다.

Codex는 지적별로 반영·추가 검증·근거 있는 미반영·사용자 판단 필요 상태를 기록한다. P0·P1을 조용히 무시하고 완료 처리하지 않는다. 서로 의견이 다르면 문서·재현 시험·수용 조건으로 확인하며 다수결이나 도구의 직위로 결론 내리지 않는다. Claude가 명시적으로 맡은 작은 수정도 Codex가 diff를 검토하고 통합한 뒤 관련 회귀 테스트를 다시 수행한다. 미해결 중요 위험은 사용자에게 알린다.

### 권장 파일 배치

### 두 도구와 여러 작업자의 충돌 방지

1. 시작할 때 저장소 상태, 현재 브랜치, 미커밋 변경, 기존 지침과 현재 작업 로그를 읽는다. 다른 사람의 변경을 자신의 변경으로 간주하지 않는다.
2. Claude의 기본 검수는 고정된 커밋 또는 변하지 않는 스냅샷을 읽는다. 병렬 수정이 승인된 경우에는 작업자별 브랜치와 별도 worktree를 사용한다. 동일 파일을 동시에 수정하지 않는다. 공유 빌드 파일·공통 인터페이스·공통 문서는 Codex가 통합 담당자로 편집한다.
3. `docs/FILE_OWNERSHIP.md`에 작업자 별칭, 브랜치·worktree, 허용 파일 또는 디렉터리, 제외 범위, 인수인계 대상, 상태를 기록한다. 소유 범위 변경은 담당자 간 확인 뒤 기록한다.
4. 브랜치가 달라도 논리적 충돌은 생긴다. 서로 다른 파일이어도 같은 인터페이스를 바꿀 때는 계약을 먼저 합의한다. Codex가 통합 담당자로서 diff와 테스트를 확인하며 순서대로 통합한다.
5. 병렬 환경이 없으면 Codex가 변경을 멈추고 검수 묶음을 만든 뒤 Claude에 전달한다. Claude가 결과를 반환하면 Codex가 수정·통합·재검증을 이어 간다. 도구를 바꿔도 메인 책임은 Codex에 남고, Claude에게 전체 작업을 다시 시작시키지 않는다.
6. 충돌을 발견하면 해당 파일 수정을 멈추고 재확인한다. `reset --hard`, 강제 덮어쓰기, 무단 삭제, 강제 push, 이력 재작성으로 충돌을 없애지 않는다. 사용자의 미커밋 변경을 stash하거나 이동하는 것도 먼저 승인받는다.

AGENTS.md·CLAUDE.md 등 기존 지침 파일은 통째로 덮어쓰지 말고 차이를 제안한다. 프로젝트 기준과 상위·하위 지침이 모순되면 그 충돌을 알리고 확인한다. 파일 지침은 도구의 실제 권한·사용자 승인·안전 제약을 대체하지 않는다.

# Agent Instructions

## Non-Interactive Shell Commands

**ALWAYS use non-interactive flags** with file operations to avoid hanging on confirmation prompts.

Shell commands like `cp`, `mv`, and `rm` may be aliased to include `-i` (interactive) mode on some systems, causing the agent to hang indefinitely waiting for y/n input.

**Use these forms instead:**
```bash
# Force overwrite without prompting
cp -f source dest           # NOT: cp source dest
mv -f source dest           # NOT: mv source dest
rm -f file                  # NOT: rm file

# For recursive operations
rm -rf directory            # NOT: rm -r directory
cp -rf source dest          # NOT: cp -r source dest
```

**Other commands that may prompt:**
- `scp` - use `-o BatchMode=yes` for non-interactive
- `ssh` - use `-o BatchMode=yes` to fail instead of prompting
- `apt-get` - use `-y` flag
- `brew` - use `HOMEBREW_NO_AUTO_UPDATE=1` env var

- 증거 수준: 합성 좌표/이력·직접 작성 음원 로컬 웹 시연, 공개 SDK 아티팩트 대조와 단일 Java 매퍼 컴파일. 실제 SDK 런타임/Android 전체 앱/실차/사용자 효과 미검증. GitHub와 최신 로컬 변경의 일치를 가정하지 않는다.
- 산출물: 심사 항목 | 사실/해석/미확인 | 원출처 URL·제목·발행/갱신일·확인일·근거 절 | J1 적용 | 반대 근거 | 다음 검증. 날짜 없으면 미표기, 출처 없으면 미확인으로 쓴다.
- 현대차·42dot·Pleos 공식 자료와 필요한 플랫폼 공식 문서를 우선한다. 공모전 사이트의 자동 수집 제한을 준수한다. 비공개 배점·수요·SDK 실행 성공을 만들지 않는다.
- Dot은 먼저 수신/범위/차단을 답하고 3~5개 핵심 근거를 텍스트로 보고한다. 별도 DOCX/새 예약은 요청하지 않았다. 기존 자체 예약의 존재·J1 초점 반영 가능 여부는 확인 요청했으며 아직 검증하지 않았다.
- 코드·공통 문서는 Codex만 수정한다. Dot은 조사 보고만 반환하며 Claude는 고정 입력 독립 검수. 공개·push·외부 연락/제출·계정·권한·결제·비밀값 전달 금지.

## 반복 운영

수신·조사 중·보고 수신·출처 검증·반영·추가 질문·차단·완료를 구분한다. 새 보고는 원문 링크와 핵심 내용을 보존하고 Codex가 원출처를 확인한 뒤 결정/API/검증 기록에 필요한 부분만 반영한다. 개발상 영향이 있는 변경은 Claude 검수를 거친다. 근거가 부족하면 동일 ID의 보완 질문, 새로운 독립 과제는 다음 ID를 쓴다. 진행 중 과제를 반복 하달하지 않는다. 연결이 끊기면 진행 상태를 보존하고 실패를 알리며 우회하지 않는다. 사용자의 중단 또는 프로젝트 종료 시 heartbeat도 중단한다.
