# 공동 디자인 검토 (claude-opus-5-5, 읽기 전용, 도구 사용 없음)

## 1. 위험·혼동 지점과 최소 수정

| 위험 | 이유 | 최소 수정 |
|---|---|---|
| 오른쪽 열에 수락·유지·종료가 함께 있음 | 결정 버튼 바로 아래에 되돌릴 수 없는 종료가 있어 잘못 누르기 쉬움 | 종료를 **왼쪽 하단 보조 버튼(테두리형)** 으로 옮김. 오른쪽 열은 결정만 담당 |
| 수락과 기존 장소 유지가 같은 무게 | 두 버튼이 나란히 비슷해 보이면 어느 쪽인지 헷갈림 | 세로로 쌓고 간격 24px. 수락은 밝은 중립색으로 채우고, 유지는 테두리형으로 둠 |
| 수락 문구가 모호함 | "수락"만으로는 무엇을 받아들이는지 알 수 없음 | **"○○로 변경"**, **"현재 장소 유지"** 처럼 장소명을 버튼에 넣음 |
| 확정 지점과 제안 지점 혼동 | 왼쪽에는 확정 장소, 오른쪽에는 제안 장소가 동시에 보임 | 왼쪽에 "확정 승차지점" 라벨을 고정. 오른쪽은 "상대 제안: ○○" 한 줄로 결정 버튼 위에 둠 |
| 상태를 회색 명도로만 구분 | 민트를 없앤 뒤에는 준비/미준비가 명도 차이로만 보임 | 텍스트와 형태로 구분: 준비는 채움 배지 "준비 완료", 미준비는 테두리 배지 "준비 전" |
| 끊김 상태에서 이전 정보가 남음 | "준비 완료"가 그대로 남으면 지금 상태로 오해함 | 상태 영역을 **"연결 확인 안 됨 · 변경 불가"** 로 바꾸고 결정 버튼을 비활성 처리. 다시확인 버튼은 이때만 상태 카드 안에 표시 |
| 내 제안이 대기 중일 때 화면이 정의되지 않음 | 오른쪽 열에 무엇을 보여줄지 정해지지 않음 | "제안 보냄: ○○" 문구와 보조 버튼 "제안 철회"를 보여줌. 장소 변경 버튼은 숨김 |
| 1920x720에서 2/3가 너무 넓음 | 시선이 길게 이동해야 함 | 왼쪽 콘텐츠는 최대 약 1100px로 제한. 오른쪽 열은 480~560px 고정 |

## 2. 480x720 세로 높이 예산 (CSS px, dp 아님)

| 구간 | 높이 |
|---|---|
| 상단 여백 | 16 |
| 앱 헤더 (픽업 약속판 / 역할 · 회차 연결) | 56 |
| 간격 | 16 |
| 상태 카드 (상태 배지 36px 글자, 확정지점 라벨 18px, 지점명 28px) | 168 |
| 간격 | 16 |
| 제안 라벨 한 줄 (평소에는 숨김) | 40 |
| 간격 | 8 |
| 결정 버튼 88 + 간격 24 + 88 | 200 |
| 구분 간격 | 24 |
| 종료 버튼 (보조, 테두리형) | 80 |
| 간격 | 16 |
| 고지 한 줄 (18px: Gleo 미연결 · 주행 중 사용 금지) | 32 |
| 하단 여백 | 16 |
| **합계** | **688 (여유 32)** |

- 너비: 좌우 여백 24씩, 버튼은 432px 꽉 채움.
- 높이가 부족하면 줄이는 순서: ① 세부 안내 접기 → ② 상태 카드 168을 136으로 → ③ 간격 16을 12로. **버튼은 76 아래로 내리지 않고, 고지 줄은 없애지 않음.**
- 평소(제안 없음)에는 결정 영역에 "장소 변경" 버튼 하나(88)만 둠. 그래서 남는 112px는 상태 카드에 줌.
- 640x960은 같은 순서로 쌓고 버튼만 96으로 키움. 남는 높이는 상태 카드에 배분.

## 3. 최종 공동 방향

**한 줄 원칙:** 공개된 Pleos 가이드의 회색조·Asta Sans·큰 고정 버튼 위계만 따름. "현대차 앱과 같다"고 주장하지 않고, 로고·브랜드 표식·시스템 UI 모사는 없음.

### 동의하는 Codex 안
- 검정 배경, 앱 자체 헤더, 실제 회차 연결 표시만 둠.
- 가로 2/3 + 1/3 구조, 세로 분할창은 위에 상태, 아래에 결정.
- 장소 변경은 전체 높이 별도 화면. 큰 장소 3개를 두고 현재 장소는 비활성 표시. 취소하면 원래 화면으로 복귀.
- native select 제거, 별도 초대 대기 화면, 영업 카피 없는 시작 화면.
- 준비 조작은 탑승자에게만.
- 장식·애니메이션·지도·ETA 없음. Gleo 미연결과 주행 금지 고지는 항상 표시.
- 같은 노드 id 유지, 서버 권한·버전·종료 보호 로직은 그대로.

### 수정 제안
1. 종료는 왼쪽 하단 보조 버튼으로 옮기고, 탭하면 별도 확인 화면을 거침.
2. 결정 버튼은 세로 배치, 간격 24, 장소명 포함 문구, 채움/테두리로 위계 구분.
3. 상태는 텍스트와 형태로 전달하고, 회색 명도에만 의존하지 않음.
4. 다시확인은 끊김 상태에서만 상태 카드 안에 나타남.
5. 장소 변경 화면에서는 장소를 탭하면 바로 제안을 보냄. 확인 단계를 더하지 않는 대신 철회로 되돌릴 수 있게 함.
6. 글자 크기: 본문 최소 18, 버튼 라벨 24, 상태 32~36.
7. 주동작은 순백 대신 밝은 회색(Pleos 버튼 토큰)을 써서 야간 눈부심을 줄임. 배경도 Pleos background 토큰 값이 있으면 순수 #000 대신 그 값을 씀.

### 반론과 한계
- **88~96px 버튼:** 화면에서 76dp 이상처럼 보일 수는 있음. 하지만 px와 dp는 같지 않고 실제 밀도·시야각 검증도 없으므로 **실차 적합성 근거가 아님.**
- **"현대차 톤":** 공개 문서의 토큰만 반영한 근사치임. 실제 현대 앱의 시각 언어와 같다는 검증은 없음.
- **운행 상태:** 실제 플랫폼 연동이 없으므로 주차 확인으로 제한을 해제하는 흉내는 계속 넣지 않음. 로컬 시연 고지는 유지.
- **488x720 이하:** 위 예산은 가장 큰 상태(상대 제안 대기) 기준. 장소 변경 화면은 버튼 3개(88×3) + 취소 + 고지로 약 520px라 여유가 있음.
- **검증 필요:** 이 시안은 양산 인증 UI가 아니며, 다섯 해상도 스크린샷을 다시 찍어 확인해야 함.

※ 요청에 따라 도구를 쓰지 않아서 계획 파일 작성과 ExitPlanMode 호출은 하지 않았습니다.
