## 변경과 검수 대응

- `multi/board.mjs`, `planner.mjs`: 수동 도착 시 출발 기준 좌표를 갱신하고 이미 이동한 origin→active 구간을 남은 추천 시간에서 제외한다. 실제 위치 관측이 아닌 사용자 도착 확인이다. 활성 지점은 계속 첫 번째로 고정한다.
- `multi/page.mjs`: 저장된 회차 조회 401/403/404에서 세션을 정리하고 새 회차/초대 안내를 표시하며 폴링을 멈춘다. 일시적 503·연결 실패는 세션을 보존한다. 참여 복구 불가 403/404/409에서는 재시도 키를 정리하고 버튼을 비활성화하며 취소/재초대를 안내한다.
- `multi/page.html`: 총 6명 제한은 취소 인원도 포함하는 기존 승인 정책임을 명시한다. 정원 도달 시 장소 변경을 위한 재초대도 새 회차가 필요하다. 제한 자체는 변경하지 않았다.
- `multi.test.mjs`, `multi-client.test.mjs`: 위 오류와 시간 계산 회귀 4개 추가.

실제 Claude Haiku5.5 읽기 검수: 최초 session `9f63669b-cd1f-403e-b5ae-683ff329f495`, 후속 `85c9eaf1-81c5-42ee-aa3c-6d9e00146288`; 둘 다 exit0/is_error=false. 최초 P1 없음/P2 네 건은 세 가지 수정과 기존 정책 문구 명확화로 처리했다. 후속 확인 요청:

1. B1 활성 지점 고정: `bestOrder`는 `order[0] !== active`를 거부하고 `visit([active], order.slice(1))`로 고정한다. 기존 active-lock 및 신규 도착 후 실제 순서/합계 시험 통과.
2. B2 폴링 예외: `setInterval`은 `run(refresh, true)`를 호출하고 `run` 내부 try/catch가 예외를 처리한다. 새 Chrome 회차 소실/새로고침 검증에서 설정 복귀를 확인했다.
3. B3 join 재시도: `join`은 같은 joinId/초대의 5분 이내 재요청에 동일 자격을 반환한다. 해당 경로는409가 아니다. 기존 도메인 멱등 시험과 응답 유실 후 복원 fake DOM 시험 통과. 종료 회차409는 복구 불가 안내가 맞다.
4. B4 문구: 취소/재초대와 총6명 한계의 예외를 같은 안내에 명시. 별도 정책 변경 없음.
