# PICKGO 카카오맵 조건부 대안 검토

2026-11-04 KST. 사용자 결정: 현대 내비를 사용할 수 없는 구조라면 카카오맵 연동을 고려하되 공모전 제출에 문제가 없는지 검증한 후 진행한다. 현대 내비를 즉시 포기하거나 카카오 연동을 무조건 승인한 것이 아니다.

## 현재 판정

**조건부 대안으로 유지, 실제 전환 보류.** 공개 공모전 자료에서 카카오 등 외부 지도 사용의 일괄 금지나 NaviHelper 필수 조항은 찾지 못했다. 이는 주최 측의 개별 허가·무감점 보장이 아니다. 카카오의 검색 응답 저장·공유 제한과 차량용 AAOS 적용 범위가 해결되지 않아 사용자 조건인 ‘문제없음’을 충족하지 못했다.

## 3. 가장 큰 차단: 확정 좌표의 저장·공유

- [2026-08-18 운영자 답변](https://devtalk.kakao.com/t/api-b2b/151176)은 사용자가 검색 결과를 선택한 경우에도 API 응답을 저장해 사용하는 것을 불허하며 사용자가 직접 입력한 내용과 구분한다.
- [2026-10-19 운영자 답변](https://devtalk.kakao.com/t/local-api-id/152212)은 검색 결과와 무관한 직접 지정 좌표는 저장 가능하나 검색 결과 위치를 재선택·확정해 저장하는 것은 허용하지 않는다고 설명한다. 선행 답변은 검색 결과의 서버 저장·회원 간 공유까지 허용한 것이 아니라고 명확히 한다. 장소 ID 단건 조회 API는 없고 저장한 ID/URL은 카카오맵 연결용으로 안내한다.
- 따라서 `카카오 검색 → 핀 확인/조정 → 확정 좌표를 서버에 저장 → 운전자와 탑승자에게 공유`를 현재 설계 그대로 허용된 것으로 보지 않는다. 실제 핀 이동으로 독립 입력이 되는 기준, 회차 동안의 임시 중계·보관 허용, 현대 내비로 좌표 전달 가능 여부는 별도 확인해야 한다. RAM·짧은 TTL·이름 변경·재클릭을 자동 면제 사유로 삼지 않는다.
- 검색 결과와 완전히 독립적인 사용자 GPS·직접 입력이나 적법한 별도 데이터는 출처를 분리해 설계할 수 있다. 다만 검색 결과를 재가공해 독립 데이터라고 부르는 방식은 채택하지 않는다.
- 질문자의 요약이나 미답변 게시물은 허가 근거가 아니다. 예를 들어 [151294](https://devtalk.kakao.com/t/sdk-poi/151294)의 질문자 설명을 승인으로 사용하지 않는다.

## 4. 차량 환경·정책

[Pleos Maps/Navigation 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/navigation-app-development-guide)는 단일 활성 경로, 명시적 전환, 주행 중 전체화면 팝업 금지, 기능과 카테고리 일치 등을 요구한다. 외부 지도 표시만으로 별도 내비 안내를 동시에 실행하지 않는다. PICKGO의 실제 기능에 맞는 카테고리를 확인해야 한다.

[카카오모빌리티 2026-09-01 답변](https://devtalk.kakao.com/t/knsdk-carplay-android-auto/151398)은 KNSDK의 CarPlay/Android Auto 미지원 및 우회 연동 불가를 설명한다. **Android Auto와 Pleos의 Android Automotive OS는 다르므로 이 답변으로 AAOS 금지를 단정하지 않는다.** 반대로 일반 Android SDK 제공만으로 차량 탑재 허가·호환을 주장하지 않는다. AAOS/차량 디스플레이 지원·라이선스·필요 계약이 미확인이다.

[운영정책](https://developers.kakao.com/terms/ko/site-policies)의 로고·저작권 고지 유지, 허위 앱 정보 금지, 데이터 사용 제한을 반영해야 한다. [사용 설정](https://developers.kakao.com/docs/ko/kakaomap/common)의 앱 활성화·플랫폼 등록·무료 쿼터 적용 계정 조건도 확인해야 한다. 이번에 계정/키/과금 설정은 변경하지 않았다. apis.map.kakao.com/terms/ 주소는 웹 도구로 본문 확보 실패하여 검토 완료 출처로 세지 않았다.

## 5. 전환 조건

1. 현대 내비의 어떤 기능이 불가능한지 특정한다: 장소검색 결과 회수/지도 조작/경로 안내를 각각 판정한다. 일시 실행 실패를 구조적 불가능으로 바꾸지 않는다.
2. 공모전 제출·PT·전시에 외부 지도와 선택한 Pleos 연동 구성이 허용되는 근거를 확보한다. 공개 자료만으로 모호한 부분은 주최 측 답변이 필요하다.
3. 카카오로부터 PICKGO의 AAOS 표시, 검색 결과와 사용자 핀의 구분, 회차별 저장·양측 공유·현대 내비 전달 조건을 확인한다.
4. 허용된 조건을 데이터 모델과 보관/삭제 정책에 반영하고 계정의 SDK/API 사용 가능 범위를 확인한다.
5. SDK 호환, 지도 고지, 물리폰/차량·에뮬레이터, UX 제한, 오프라인/쿼터 실패를 시험한다.

조건 충족 시에는 사용자가 이미 승인한 조건부 범위 안에서 카카오 대안을 진행한다. 조건이 해결되지 않으면 공급자 교체 경계 설계까지만 유지하고 본연동/제출가능 판정을 보류한다.

## 6. 필요한 외부 확인 문안 — 준비만, 미발송

### 공모전 운영사무국

PICKGO는 Pleos Connect 차량 앱과 탑승자 웹/앱이 픽업 지점을 합의하고 위치를 공유하는 서비스입니다. 현대 내비 검색 결과 회수 또는 지도 조작 API를 이용하기 어려운 경우 카카오맵의 장소검색·지도 표시·핀 조정을 사용하고, 가능한 현대 내비 안내 및 Pleos 음성·차량 UX 연동은 유지하려 합니다. 이 구성이 1차 제출, 2차 PT 시연, 선정작 전시에 허용되는지, NaviHelper 필수 여부나 외부 지도에 관한 별도 제한·표시 요건이 있는지 확인 부탁드립니다. 내비 안내까지 외부 공급자로 대체할 때 추가 제한도 구분해 안내 부탁드립니다.

### 카카오 지도/API 담당자

Android Automotive OS 기반 Pleos 차량 화면 및 탑승자 휴대폰에서 카카오 지도/장소검색을 이용하는 픽업 앱을 검토하고 있습니다. 검색 기준 장소 주변에서 사용자에게 승차 후보를 보여주고, 사용자가 핀을 조정한 좌표를 한 픽업 회차 동안 서버에서 보관·중계하여 운전자와 탑승자에게 보여주며 현대 NaviHelper 목적지로 전달하려 합니다. (1) AAOS/차량 디스플레이 사용과 공모전 APK·영상·전시 배포에 별도 허가/계약이 필요한지, (2) 검색 결과와 독립적인 사용자 지정 좌표의 기준, (3) 임시 저장/양측 공유/현대 내비 전달 허용 범위와 삭제 조건, (4) 허용 가능한 대체 구조와 로고/출처 표시 요건을 확인 부탁드립니다. 검색 결과 재확정만으로 저장이 허용되지 않는 152212 답변을 전제로 검토 중입니다.

외부 문의는 프로젝트 DEVELOPMENT_GUIDE.md 11절의 별도 발송 승인 대상이다. 이번 사용자 지시는 검증과 조건부 채택이며 문의 실제 발송까지 명시하지 않아 문안만 준비했다.
