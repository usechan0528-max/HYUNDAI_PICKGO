# 픽업 약속판 · 수동 도착·탑승 0.3.0

운전자와 탑승자가 같은 회차의 준비 상태와 승차지점 변경을 확인하는 로컬 웹 앱입니다. **실제 서버 상태를 두 화면이 공유합니다. 장소는 합성이며 실제 Gleo·Pleos SDK 연동이나 Android APK가 아닙니다. 주행 중 사용하지 마세요.**

## 실행

Node.js 22 이상(실행 검증: Windows, Node 24.19.0). 외부 패키지 설치 없이 저장소 루트에서:

```powershell
node experiments/pickup-board/server.mjs
```

[픽업 약속판 열기](http://127.0.0.1:4180). 정확히 `127.0.0.1`을 사용하세요. `localhost` 및 외부 Host는 거부합니다. 포트를 바꾸려면 PowerShell에서 `$env:PICKUP_PORT='4181'`을 설정한 뒤 실행합니다. 서버 중지는 실행한 터미널에서 Ctrl+C입니다.

## 두 화면 시연

1. 승차지점을 고르고 **약속 만들기**를 누릅니다.
2. **탑승자 화면 열기** 링크를 새 탭으로 엽니다. **탑승자로 참여**를 누릅니다. 같은 컴퓨터에서 두 역할을 확인하는 방식입니다.
3. 탑승자가 **준비됐어요 / 아직 준비 중**을 선택합니다. 운전자 화면은 2초 주기로 갱신하며 **다시 확인**도 가능합니다.
4. 어느 쪽이든 **다른 장소 제안**을 누르고 큰 장소 버튼을 선택합니다. 기존 지점은 그대로 유지되고 제안이 별도로 표시됩니다.
5. 상대가 **이 장소로 변경 / 현재 장소 유지**를 선택합니다. 제안자는 자기 제안을 수락하지 못하며 **제안 철회**는 가능합니다.
6. 운전자가 확정 지점에 도착한 뒤 **도착했어요**, 탑승자가 실제 차량에 탄 뒤 **탑승했어요**를 직접 누릅니다. 준비 상태나 위치로 자동 확정하지 않습니다.
7. 탑승 전에는 운전자가 **도착 표시 취소**, 탑승 확인 후 종료 전에는 탑승자가 **탑승 확인 취소**로 실수를 되돌립니다.
8. 탑승 확인 후 **픽업 완료로 종료 → 완료 확정**은 완료로 기록합니다. 그 전 **약속 취소 → 약속 취소 확정**은 탑승 미완료 취소로 기록합니다. 두 역할 모두 종료할 수 있고 **계속 진행**은 확인창만 닫습니다. 종료 뒤에는 수정할 수 없습니다.
9. 도착 후 장소 변경을 수락하면 이전 도착 표시를 지웁니다. 제안 대기 중에는 도착·탑승 확인이 잠기며, 탑승 확인 후 준비·장소 변경이 잠깁니다. 종료 확인 중 상대가 상태를 바꾸면 확인창을 닫고 다시 확인해야 합니다.

초대 링크는 일회용이며 링크를 아는 사람이 탑승자로 참여할 수 있습니다. 실제 연락처나 주소를 입력하지 않습니다. 참여한 탭의 새로고침은 역할을 복원하지만 탭을 닫아 sessionStorage를 잃으면 복구하지 못합니다. 참여 전에 초대 화면을 새로고침했다면 운전자 화면에서 초대 링크를 다시 여세요.

## 저장과 실패 처리

- 서버 메모리 저장: 재시작 시 소실, 최대 24시간 유효. 만료 데이터는 다음 서버 요청 때 정리됩니다. 최대 100회차·회차당 1000변경의 시연 상한입니다.
- 2초 조회, 요청 4초 제한, 요청 시작으로부터 6초 이내만 클라이언트 최신 표시. 서버 조회 권한의 유효기간은 8초입니다. 숨겨진 화면은 현재 미확인 처리하고 복귀 후 조회합니다.
- 연결 실패 시 이전 지점·제안은 명확히 과거 기록으로 표시하고 준비 상태는 현재 미확인, 변경 버튼은 비활성화합니다. 서버 재시작 후 사라진 회차는 오류와 새 시작 버튼으로 안내합니다.
- 권한·버전·조회 유효기간·요청 ID·제안 ID·종료 여부를 서버에서 검사합니다. 실패한 변경을 자동 재전송하지 않습니다. 최신 상태를 확인한 후 다시 선택합니다.
- 브라우저와 서버의 인증 값은 이 로컬 시연에서만 쓰는 임시 참여 권한입니다. 운영 계정 인증, 다중 기기 공유, 지속 저장, 암호화 전송, 사용자 복구, 부하 검증은 미구현입니다.

## 검증

```powershell
node --test experiments/pickup-board/*.test.mjs
node --check experiments/pickup-board/app.mjs
```

도메인·실제 HTTP 11시험과 fake DOM/network 회귀6개, 총17시험 통과. 실제 브라우저 두 역할 생성/참여/준비/제안/수락/거절/철회/종료/새로고침 및 서버 중단·재시작 확인. [검수와 한계 보고서](../../docs/PICKUP_BOARD_MVP_2026-11-02.md).

## 범위 밖

실시간 ETA, 상시 위치추적, 자동 문자 읽기·송신, 학교 제휴, 주정차 가능성·안전 보장, 실제 Gleo 호출, CarUxRestrictions, SDK·실차·release APK. Gleo는 향후 이 앱의 회차 상태를 조회/변경하는 접점으로 검토할 수 있으나 이번 MVP에 연동 성공 증거는 없습니다. 카카오맵·카톡 등 대비 양측 입력량·반복 사용 가치도 아직 실측하지 않았습니다.

외부 런타임 패키지·이미지 없이 로컬 Asta Sans 폰트를 사용합니다. 폰트와 OFL 1.1 라이선스는 fonts/에 포함했습니다. 이전 J1 차량 시안의 중립 검정·차콜·흰색과 큰 버튼을 계승했습니다. [차량 화면 디자인·Claude 협업 검증](../../docs/PICKUP_BOARD_DESIGN_2026-11-02.md). CSS 버튼 높이는 프로젝트 기준이며 실제 차량 dp 적합성 인증은 아닙니다.

## 각진 디자인과 에뮬레이터 검토
패널0px/버튼2px 모서리로 조정했습니다. Pleos 에뮬레이터에서 생성·종료확인·취소를 확인한 [검토용 실행 앱](emulator-preview/README.md)과 [검증 보고서](../../docs/PICKUP_BOARD_EMULATOR_DESIGN_2026-11-02.md)를 참고하세요. 웹 제품의 native이식/SDK연동완료와 구분합니다.

## 수동 상태 기능 검증 · 2026-11-03
최종27시험(도메인/실제HTTP18 + fake DOM9) 통과. 실제Chrome 두역할 도착→장소변경/도착초기화→탑승→실수취소/종료확인무효화→완료와 서버단절잠금 확인. 작은 창은 내용 영역 스크롤로 버튼 겹침을 방지합니다. 잠금 해제 후 Pleos에서 소실 회차 안내→새 약속 복구→도착 전 표시→미탑승 취소를 확인했습니다. 두 역할 도착·탑승 전체 흐름의 실제 UI 검증은 Chrome에서 수행했습니다. [상태 계약·검수·증거](../../docs/PICKUP_BOARD_STATUS_2026-11-03.md).


## Gleo 연동 준비 · 2026-11-03
조회·수동 도착 두 명령의 내부 어댑터와 후보 schema, 기본 거부/일회성 요청/역할·신선도 시험을 추가했습니다. 현재 웹/Android/Gleo에는 연결하지 않았습니다. 실제 연동은 승인·호출자 계약·native 세션과 UX 공급자 연결이 남아 있습니다. [구현과 연결 절차](gleo/README.md) · [검증·차단 보고서](../../docs/PICKUP_GLEO_READINESS_2026-11-03.md).
