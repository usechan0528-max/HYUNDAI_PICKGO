# J1 운행 맥락 로직 실험

D-014 주력안 보완을 위한 로컬 합성 실험입니다. 기존 주차 MVP와 분리되어 있습니다.

```sh
node --test experiments/journey-context/core.test.mjs
```

외부 의존성·네트워크·위치 수집 없음. `core.mjs`는 합성 구역 ID의 이동 순서를 이미 종료된 같은 프로필의 이력과 비교합니다. 공통 구간에서는 후보를 유지하며 한 후보만 남아도 확정 목적지로 표시하지 않습니다. 분기와 운행별 선호가 추천 주제를 바꾸는지, 입력 실패 시 취향으로 돌아오는지, 다음 큐 교체가 현재 재생 ID를 보존하는지 시험합니다.

이 코드는 GPS 경로 예측기, SDK 어댑터, 실제 미디어 플레이어 또는 앱 UI가 아닙니다. 추천 카탈로그는 `testOnly: true`인 가상 메타데이터이며 실제 오디오나 재생 권리를 확보한 것이 아닙니다. 사용자가 입력한 선호 가중치와 구역 일치 규칙은 시험용입니다. 확률·정확도·만족도 점수를 출력하지 않습니다.

현재 한계:
- 정확한 구역 prefix 일치만 사용해 GPS 노이즈·우회·부분 이력을 처리하지 못합니다. 매칭 실패는 미확인입니다.
- 목적 라벨은 과거 사용자가 확인했다는 합성 전제입니다. 시간대·요일·방향 추정과 거리/잔여시간 추정은 아직 구현하지 않았습니다. 거리/시간 필드는 과거 여정의 값입니다.
- 삭제 시험은 메모리 이력·파생 맥락·다음 추천의 무효화를 검증하며 영구 저장소 삭제는 구현하지 않았습니다.
- 큐 정책은 다음 ID를 제한하는 상태 모델이며 실제 재생·오디오 포커스·수명주기 검증은 없습니다.
- 주행 UX 제한은 플랫폼 어댑터 미구현입니다. 목적지 확인 출처는 호출자가 보장해야 하며 이 모듈이 주차 여부를 검증하지 않습니다.
- 같은 가상 카탈로그를 사용하는 A/B/C 합성 기능 비교를 추가했습니다. 선택수고 감소나 차량 맥락 우위는 아직 측정하지 않았습니다.

다음: 실제 관측 계약으로 연결하기 전 입력 경계와 세션/프로필 전환을 검증하고, 동일 fixture의 시간대 기준선과 맥락 추천을 비교합니다. 합성 비교도 사용자 효과로 확대하지 않습니다.

입력은 내부 합성 fixture 계약입니다. 외부 JSON 전체 스키마 검증은 아직 없습니다. 위치/프로필/동의 변화는 JourneySession.tick으로 반영해야 하며, 순수 함수 반환 객체를 별도 저장하면 자동 무효화되지 않습니다. SDK 어댑터 연결 전에 이 통합 계약을 검증해야 합니다.

## A/B/C 기능 비교

```sh
node experiments/journey-context/compare.mjs
node --test experiments/journey-context/*.test.mjs
```

A는 기본 취향, B는 과거의 같은 출발 시간슬롯과 취향, C는 관측된 구역 이동 순서와 취향을 사용합니다. 시각 슬롯은 fixture의 명시 입력이며 시간대/달력 처리 구현이 아닙니다. 세 방식은 같은 가상 콘텐츠와 기본 선호를 사용합니다. C가 B에 경로를 단순 추가한 중첩 모델은 아니며 서로 다른 맥락 입력 전략의 기능 비교입니다.

|합성 사례|A|B|C|
|---|---|---|---|
|평소 아침 출근|과학|뉴스|뉴스|
|아침 장보기|과학|뉴스|과학|
|경로 분기 전|과학|뉴스|과학|
|처음 가는 경로|과학|뉴스|과학(취향 대안)|
|위치 권한 거부|과학|과학|과학|
|운행별 선호 없음|과학|과학|과학|

두 가상 주제와 임의 가중치가 결과를 결정합니다. 정답·사용자의 선택이 없으므로 승자나 정확도를 계산할 수 없습니다. 경로 기반 추천을 유리하게 설정한 실제 효과 시험이 아니며, 추천이 달라질 수 있는 코드 경로를 드러내는 고정 예제입니다. 공통 구간에서 C가 과학을 고르는 것도 목적지를 맞혔다는 뜻이 아닙니다. 아직 최소값 적합도 규칙의 보수성·후보 수 편향을 검증하지 않았습니다.

### 비교 검수 처리
Haiku5.5 정적 검수 후 B에도 유효한 now/startedAt 조건을 적용했다. 동일 출발시각에 종료한 이력 배제와 잘못된 시계의 양쪽 대안을 시험한다. B가 위치 관측 최신성을 사용하지 않는 것은 입력 전략의 차이이며 위치 기반 C만큼 정보를 요구해 비교 조건을 바꾸지 않는다. 공통 카탈로그를 단일 항목으로 줄인 시험의 이름은 실제 검증 범위에 맞춰 수정했다.

QueuePolicy.current는 재생기 이벤트로 호출자가 넣는 계약이며 재생기 미구현을 숨기지 않는다. 현재 코드에서 프로필 전환은 같은 운행 세션의 갱신 예산을 유지하는 의도다. 세션을 종료하고 새로 시작할 때만 예산을 새로 부여한다. 최소 적합도(min) 대신 평균/최대를 쓰는 민감도 분석은 미실행이며 추천 우월성을 주장하지 않는다.

## 실제 SDK 선언과의 컴파일 대조

`java/LocationSnapshotMapper.java`는 공식 FusedLocation1.1.3 실제 AAR의 공개 getter에 대해 컴파일한 최소 경계 실험입니다. 다운로드 URL/해시/명령은 docs/evidence/j1-sdk-boundary-2026-11-02.json에 있습니다. SDK 바이너리는 임시 디렉터리에만 있습니다.

이 Java 코드는 Android 프로젝트나 실행 어댑터가 아닙니다. raw SDK 시각의 기준과 confidence 의미를 아직 확정하지 못해 합성 JS 추정기와 연결하지 않았습니다. 위경도 유효성 외 heading/altitude/confidence 품질은 검증하지 않으며 raw 보존만 합니다. 수신 시각만으로 마지막 위치가 최신임을 보장하지 않습니다. Java17 대상 컴파일 성공은 Android desugaring/배포 호환성 증거가 아닙니다.

### 내비 입력 경계 추가
`java/NavigationSnapshotMapper.java`는 실제 navi-data3.0.4의 DrivingInfo/DrivingState getter로 단일 컴파일했다. 공개 source 주석에 따라 현재 위치→목표 예상시간은 초, 거리값은 출발점 기준 raw로 구분한다. 시간0은 도착, 수신시각은 원천 신선도라고 간주하지 않는다. 음수시간/데이터없음을 별도 상태로 반환한다. 이름·주소·POI는 복사하지 않는다.

독립 javac에서 Kotlin annotation 누락 경고2개가 있었으며 실제 콜백 수신/Android실행은 하지 않았다. 현재 경로와 이벤트의 연관 및 순서·취소 후 늦은 응답·시간 품질을 검증한 다음 추천기로 연결해야 한다.

## 좌표 입력 실험 (합성 시연 연결)
coordinates.mjs는 합성 위경도 기록을 거리 허용범위 안에서 순서를 유지하며 비교한다. 공통구간 후보유지·약한좌표흔들림·분기·이탈·역행·입력거부 등 7개시험을 추가했다. 이 지점에서 사용자 D-015를 받아 자동이어듣기를 우선작업했다.

실제SDK 관측은 source/시계계약 미검증으로 거부한다. tolerance60m와 maxAdvance2는 시험설정이며 운영추천/정확도기준이 아니다. 도로맵매칭·연속선분투영·샘플간격차이·실제GPS노이즈분포·우회복귀를 해결하지 않는다. 이미 관측한 점만 비교하며 미래/다른프로필 이력을 제외한다. 현재 로컬 시연의 C 방식은 관측 모듈이 만든 합성 좌표를 이 추정기에 공급한다. 실제 SDK 매퍼 연결은 아니다.


### 좌표 시연 연결
JourneySession에 추정 함수를 주입해 기존 구역 실험을 보존하면서 좌표 추정기를 선택한다. demo/observations.mjs의 원점·공통구간·두 분기 관측은 모두 만들어낸 좌표다. ‘합성 좌표 흔들림’ 장면은 각 관측에 서로 다른 작은 위경도 오프셋을 적용한 사례이며 실제 GPS오차분포를 재현하지 않는다. 시연 조작이 이전의 관측 배열을 바꾸는 방식이므로 실시간 수집/온라인 누적처리는 아직 없다. 기존 자동이어듣기·종료·프로필/권한무효화는 유지한다.

좌표 검수 후 경계: 허용거리60m는 매칭 반경이지 GPS정확도나 목적지확률이 아니다. 점마다 다른 좌표오프셋과 시드고정20경로를 논리시험했으며 실측 오차분포를 사용하지 않았다. 가까운 경로의 반경이 겹치면 복수후보를 남긴다. 연속관측30초초과공백, 이력128개/관측256개/경로점512개초과, 정렬중200000비교초과는unknown으로전체중단한다. 이 수치는 개발 실험의 자원한도이며 실측운영설정이 아니다. 시작점은 각기록의첫좌표와일치해야하므로중간경로시작·우회복귀는해결하지않는다. 정지중제자리관측은허용하되추가확신으로해석하지않는다.

후속검수한계: maxGapMs는관측끼리의간격만검사하며 startedAtMs→첫관측지연은검사하지않는다. 현재fixture는관측세트를통째로재생하므로실제운행시작시각을검증하지않는다. 실제입력연결전이계약을확정해야한다. 이력128개초과시전체unknown은실험한도이며장기사용제품에는동의·보관기간·검색창정책을별도설계해야한다. 현재한도를근거없이운영권장값으로제시하지않는다.

## 로컬 취향·이어듣기 저장
반복 조작 감소를 위해 차주 시연의 취향과 마지막 미완료 콘텐츠 ID/재생초/길이/저장시각만 localStorage의 전용키에 저장한다. 위치·좌표·경로·합성 관측은 저장하지 않는다. 초기 화면은 취향과 미완료 항목을 복구하지만 자동으로 소리를 내지 않으며 이동 시작 버튼 한 번으로 이어듣는다. 7일이 지난 항목, 미래시각, 잘못된JSON/스키마,없는콘텐츠,끝까지들은항목은복구하지않는다. 이 유효기간은 시연정책이며 운영정책검증이 아니다.

게스트는 쓰지 않으며, 저장 차단/실패 시 현재 듣기는 계속한다. 시연 처음부터는전용키를지우고새로재생하거나취향을바꾸기전에는다시저장하지않는다. 자동저장은2초단위timeupdate와명시종료/pagehide에서수행한다. 강제종료/브라우저충돌의정확한최종위치는보장하지않는다. 서버로전송하지않으며사용자가브라우저사이트데이터를지워도삭제된다.

## 온라인 관측 입력 경계 (2026-11-02)
`coordinate-stream.mjs`의 CoordinateStream은 한 점씩 받은 합성 관측을 기존 추정기와 추천기에 연결하는 독립 실험입니다. 현재 웹 시연의 화면/입력 동작은 그대로이며 실제 SDK 어댑터와 UI에 자동 연결하지 않았습니다.

실행: `node experiments/journey-context/replay-stream.mjs`. 공통 구간 복수후보→출근 분기→관측 만료→종료 뒤 콜백 거부를 좌표 없는 결과로 출력합니다.

계약: begin은 합성 source/차주 식별/명시적 동의·권한과 시작시각을 요구합니다. 관측·수신·조회 시각은 같은 합성 시계입니다. 시작→첫 관측 및 관측 간 간격은 30초 이내, 수신 시 관측 나이도 30초 이내입니다. 관측 시각은 엄격히 증가하고 수신/조회는 역행하지 않습니다. 30초는 실험 한도이지 검증된 운영값이 아닙니다. 오류/한도초과 후에는 새 begin이 필요합니다. 조회 시 관측 만료는 unknown을 반환합니다. 자동 타이머는 없으므로 호출자가 주기적으로 context를 조회해야 합니다.

호출자가 동의·권한 상실/프로필 변경/연결 단절 시 revoke하고, 재개 시 begin해야 합니다. begin의 불투명 토큰으로 이전 콜백을 구분합니다. 점은 복사해 메모리에만 최대256개 보관하며 revoke 시 제거합니다. 실제 SDK 시계 의미를 확인하기 전 source=pleos는 거부합니다. 임의로 수신 시각을 SDK 관측 시각으로 대체하면 안 됩니다. 장기 운행의 윈도우 이동/중간 시작/우회 복귀는 미구현입니다.

Claude 검수 후 첫 관측은 관측시각뿐 아니라 첫 **수신시각**도 시작 후30초 이내로 제한했다. 이후 관측이 없어서 stale이 된 경우, 관측 간격30초 이내 및 수신/조회 비역행을 만족하는 새 관측으로 복구할 수 있다. 첫 관측 기한 만료는 세션을 종료한다. 중복 관측/오류/257번째 입력은 세션 전체를 폐기하는 보수적 실험 정책이다. 권한·동의 상태 감시는 이 클래스 밖의 필수 책임이며 UI/SDK 연결 전 revoke 통합 시험이 필요하다.
